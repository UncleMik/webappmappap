# wep_pril — статьи и недельные материалы

Рабочий каталог: `/opt/wep_pril` на сервере `129.101.119.250`.
API: `https://129.101.119.250/api/articles`.
Фронт: https://unclemik.github.io/webappmappap/.

Здесь хранится код API статей и недельных материалов, не полный бэкенд школы.
Авторизация, GetCourse, админ-панель, чат и платные права не реализованы.
Существующий открытый просмотр статей сохранён. API выдаёт только записи
со статусом `published` и доступом `public`. Изменение контента через HTTP
не разрешено; служба запускается отдельным непривилегированным пользователем.

## Каталоги сервера

```
/opt/wep_pril/
  backend/                  Node.js API и инструмент импорта
  data/articles.sqlite      тексты, названия, недели, ссылки на иллюстрации
  uploads/articles/         WebP с именами по хешу исходного файла
  uploads/articles/originals/ все исходные PNG, недоступные через HTTP
  uploads/weekly/          иллюстрации недель с именами по SHA-256
  backups/                  семь последних завершённых резервных копий
  deploy/                   systemd, nginx, Certbot, исходный импорт и отчёт
```

Код хранится в Git; база, картинки и сертификаты в Git не включаются.
Материалы в `docs/content/pregnancy-articles/` — архив исходного документа
и редакционных источников. Они не публикуются в Pages и не используются
в работающем интерфейсе. Рабочий источник статей — серверная база.

## API

- `GET /api/health` — состояние сервиса и число опубликованных статей.
- `GET /api/articles` — заголовки, недели, время чтения и картинки без текста.
- `GET /api/articles?week=27` — подборка выбранной недели.
- `GET /api/articles/pregnancy-001` — статья с текстовыми блоками.
- `GET /uploads/articles/<имя>.webp` — изображение.
- `GET /api/weekly-content` — материалы «Малыш» и «Мама», календарь по неделям 1–42 и пояснения к отдельным неделям.
- `GET /uploads/weekly/<SHA-256>.webp` — иллюстрация недели.

Списки и статьи кешируются на 60 секунд, поддерживают ETag. Картинки
кешируются на 30 дней: изменение оригинала создаёт новое имя файла.
Изображения загружаются лениво. Сжатие WebP сохраняет каждый пиксель
и размеры исходника, уменьшение разрешения не используется.

## Импорт и обновление

1. Подготовить JSON со статьями и картинки вне публичного репозитория.
   `tools/prepare-server-articles.py` проверяет архив против инвентаря Drive,
   сопоставляет названия и создаёт WebP с проверкой пикселей и SHA-256.
2. Создать резервную копию: `python3 /opt/wep_pril/deploy/backup.py`.
3. Загрузить картинки и JSON на сервер.
4. Импортировать:

   ```sh
   node /opt/wep_pril/backend/import-articles.mjs \
     /opt/wep_pril/deploy/import/articles.json \
     /opt/wep_pril/data/articles.sqlite /opt/wep_pril/uploads
   ```

Импорт выполняется одной транзакцией, сохраняет существующие статус и
правило доступа. Несопоставленные иллюстрации перечислены в отчёте импорта;
случайные картинки вместо них не назначаются. Изменённый контент доступен
без публикации кода фронта и перезапуска службы после истечения кеша.

## Эксплуатация

Недельный исходник находится в `backend/seed/weekly-content.json`, изображения —
в `backend/seed/uploads/weekly/`. Перед импортом скопировать изображения в
`/opt/wep_pril/uploads/weekly/`, сделать резервную копию и выполнить:

```sh
node /opt/wep_pril/backend/import-weekly-content.mjs \
  /opt/wep_pril/backend/seed/weekly-content.json \
  /opt/wep_pril/data/articles.sqlite /opt/wep_pril/uploads
```

Импорт проверяет наличие всех 42 недель каждого раздела, структуру данных и
наличие изображений до записи в базу. Все записи обновляются одной транзакцией;
ранее выставленные `draft` и `restricted` сохраняются. API отдаёт только
`published` + `public`. Изменения текста становятся доступны после 60 секунд
кеша API; новое имя иллюстрации соответствует новому содержимому файла.

Node.js 24, SQLite из `node:sqlite`, nginx и Certbot. Node.js слушает
только `127.0.0.1:3000`; наружу API отдаёт nginx по HTTPS.
Настройки запуска находятся в `deploy/`. Секретный ключ сертификата —
только `/etc/letsencrypt`, пароли в проекте не хранятся.

```
systemctl status wep-pril
journalctl -u wep-pril --no-pager -n 50
systemctl list-timers 'wep-pril-*'
```

Сертификат IP короткоживущий: обновление проверяется дважды в сутки,
после обновления nginx перечитывает сертификат. Резервная копия базы
через SQLite Backup API и архив всех картинок создаются ежедневно.
Копии на том же сервере защищают от ошибок обновления; внешнее резервное
хранилище пока не подключено.

Для восстановления: остановить `wep-pril`, сохранить текущую базу,
восстановить `articles.sqlite` и `uploads/` из одной завершённой копии,
выдать пользователю `wep-pril` чтение базы, запустить службу и проверить
API и статью на фронте. Рискованное восстановление предварительно согласовать.

Проверки: `node --test backend/test/*.test.mjs` из корня проекта.
