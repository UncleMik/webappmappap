Здравствуйте! Спасибо, информация понятна.

Для кодов авторизации выбрали Unisender Go. Нужны аккаунт школы, отдельный проект приложения, подтверждённый домен и отправитель, рабочий Reply-To, проверка разрешённой отправки и лимитов. Перед подключением получаем адрес API и ключ проекта защищённым способом.

По Unisender Go нужно подтвердить тариф, стартовые квоты и возможность их увеличения под ожидаемый пик входов, затем проверить отправку на Mail.ru, Яндекс и Gmail. Выбор сервиса сам по себе не подтверждает подключение или готовность доставки.

Для отправителя предлагаю отдельный поддомен, например `login@notify.legkierody.ru`. После согласования сервиса подготовим точные записи DNS для подтверждения домена и подписи писем. Настройку нужно выполнить с учётом существующей почты и отправки GetCourse.

Подскажите, какой адрес сейчас надёжно принимает обращения пользователей? Его укажем для ответов на письма. `info@legkierody.ru` сможем использовать после подтверждения входящей доставки.

Изучили официальную [схему Tech API GetCourse](https://getcourse.ru/pl/postback/redoc/schema). В ней есть чтение пользователя по email, покупок, тренингов и групп. Теперь нужно проверить работу этих методов с ключами школы и фактическое представление доступов:

1. Проверить `/user/get-fields` по email и `/user/get-purchases`, `/user/get-trainings`, `/user/get-groups` по ID этого пользователя. Просим обезличенные примеры ответов; существующие данные, группы и покупки должны сохраняться.
2. Если согласуем передачу бесплатных регистраций в GetCourse — создавать карточку без заказа и оплаты, без дублей при повторной отправке. Просим уточнить, какие письма и процессы запускает такое создание.
3. Уточнить смысл `state`, `is_actual`, `is_payed`, сроков и их часового пояса. В схеме `state` может быть пустым, ID предложения в покупке не описан. Как представлены действующий доступ, бессрочный доступ, возврат, заморозка, ручное закрытие и продление? Можно ли определить предложение отдельным чтением заказа?
4. Проверить `/common/get-trainings` и `/common/get-groups` для согласования каталога и групп, через которые школа выдаёт доступ к чатам.
5. Проверить уведомления об изменениях покупки и групп. В `/set-uri` описаны события заказа, но отдельные события всех изменений доступа не перечислены. Можно ли покрыть их callback в процессах? Какие изменения вызывают уведомление, как подтверждается его подлинность и что происходит при ошибке доставки?

В документации Tech API указана авторизация парой «ключ разработчика + ключ API школы». Просим подтвердить необходимые ключи и разрешения, возможность работы с обычным ключом из раздела «АПИ», если она есть, и лимиты именно Tech API. При необходимости уточните это в поддержке GetCourse; личные данные учениц в примерах не нужны.

Для чтения нужен отдельный доступ. Запись пользователей понадобится при согласованном создании карточек; права для настройки подписок на события проверим отдельно. Изменять заказы и оплаты через приложение не планируем. Секреты будем хранить на сервере; способ передачи согласуем перед подключением.

Документы посмотрели; подготовили отдельные проекты текстов для бесплатного аккаунта, служебных писем и рекламных согласий. Для приложения просим проверить и адаптировать:
