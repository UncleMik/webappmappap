# Пятиминутная проверка платного доступа

23 октября 2026 пользователь согласовал: при открытии курса или урока
использовать результат GetCourse не дольше пяти минут. После истечения срока
платный материал закрывается, если новое чтение не удалось.

## Реализация

`backend/auth/course-checks.mjs` получает из Tech API покупки, доступные
тренинги и минимальные статусы ответов на задания. ID GetCourse берётся только
из связи текущей внутренней карточки `auth_users`. В отдельной PostgreSQL
таблица `course_access_checks` хранит один последний результат на ученицу:
ID продукта и тренинга, период и флаги покупки, ID урока, статус и время
ответа. Тексты ответов, комментарии, email, суммы, названия тренингов и
произвольные поля API не сохраняются. Клиент получает статусы через
`GET /pl/api/v1/user/get-lesson-answers` и сразу сокращает ответ до этих полей;
учебные задания в приложении пока нельзя выполнять. Описание API:
[схема Tech API](https://getcourse.ru/pl/postback/redoc/schema).

Снимок имеет `version: 2`; прежний `version: 1` не считается достаточным и
обновляется при следующем запросе. Срок отсчитывается от **начала** чтения,
составляет максимум 300000 мс и дополнительно ограничен CHECK в PostgreSQL.
В момент точного истечения результат недействителен. Повторный вход, новый
объект сервиса, ошибка GetCourse или БД его не продлевают. Пустой успешный
ответ заменяет прежние покупки; ошибка не означает отсутствие покупок.
Параллельные запросы одной ученицы объединяются, аренда в PostgreSQL не даёт
двум экземплярам одновременно обновить карточку. Массовой или фоновой
синхронизации всей школы нет.

`backend/course-materials.mjs` читает существующую SQLite, которую служба
входа открывает **только для чтения**. Приватный каталог состоит из 122 разделов и 749 уроков; отдельно
импортирована проверенная политика выдачи для каждого раздела и урока.
Отсутствующая SQLite, неполная или повреждённая политика и сбой проверки прав
дают безопасный 503 на платных маршрутах, сохраняя обычный вход и бесплатные
материалы. Черновики с `delivery_status='unavailable'` не стали публичными
записями: материал читается только через отдельный модуль после проверки прав.

`GET /api/auth/course-check` возвращает только `verification: "current"`,
`checkedAt`, `expiresAt`. Три маршрута выдачи:

- `GET /api/auth/courses` — список доступных продуктов с количеством читаемых уроков;
- `GET /api/auth/courses/<productId>` — доступные разделы и уроки продукта;
- `GET /api/auth/courses/<productId>/lessons/<lessonId>` — текст выбранного урока.

Все четыре маршрута требуют действующую сессию и заполненный профиль; сервер
берёт ID ученицы из сессии, а не из URL или тела запроса. Положительные ID в
пути не расширяют права. Ответы имеют `Cache-Control: no-store`: без входа —
401, без профиля или конкретного права — 403, при невозможности проверки —
503. Адреса платного видео, покупки, ID GetCourse ученицы и служебные ссылки
в ответ не входят. Маршруты материалов возвращают `checkedAt`, `expiresAt`,
`validUntil`, `serverTime`: последняя граница не позже срока проверки, покупки
и всех необходимых звеньев пути к уроку.

Существующие страницы «Мои курсы» и читатель статьи используют общую проверку
срока. Они очищают платный материал в момент ближайшей границы, при скрытии
вкладки, уходе со страницы, возврате из кеша браузера и ошибке обновления;
после возврата запрашивают право заново. Сервер остаётся решающей стороной
каждого нового запроса.

## Как принимается решение по продукту и уроку

Для продукта нужны одновременно: покупка **именно его** ID с `is_actual=1`,
`state=null` и допустимым периодом; текущее время внутри периода; его корневой
тренинг в актуальном списке `getUserTrainings`. `is_payed=1` не требуется:
одна оплаченная покупка в школе вернула `is_payed=0`. Список доступных
тренингов без покупки не открывает платный продукт. Старые покупки тех же
продуктов учитываются по своим фактическим срокам, новые тарифы их не
продлевают. Неизвестные периоды, будущие/истёкшие даты и противоречивые
данные остаются закрытыми. Время GetCourse без пояса трактуется как московское
UTC+03:00; явный пояс в timestamp учитывается.

На каждом пути от купленного корня к уроку проверяется доступность каждого
раздела по GetCourse. Поддерживаются активные типы `none` (дочерний раздел
требует собственной покупки) и `parent` (наследование права родителя).
Покупка корня не открывает некупленный дочерний `none`. Типы с группами,
последовательным завершением другого тренинга и неизвестные варианты пока
закрыты. В интерфейсе GetCourse сохранённые ID групп и «завершить другой
тренинг» могут оставаться у раздела, когда выбран другой radio-тип доступа;
это не самостоятельные права. Выбранный `parent` с такими скрытыми остатками
обрабатывается как `parent`. Основание:
[типы доступа и отдельные настройки подтренингов](https://getcourse.ru/blog/276090).

Явно скрытый урок не выдаётся. При общем расписании `visibility=2/3`
ограничивает урок **только при наличии даты начала**: до даты он закрыт,
без даты одна лишь настройка видимости его не закрывает. GetCourse указывает
московское время. Уроки 2/3 с индивидуальным расписанием и неизвестные даты пока закрыты:
[правила расписания GetCourse](https://getcourse.ru/blog/276148).

Стоп-урок ограничивает только последующие уроки **того же тренинга**.
Для продолжения нужен свежий статус `accepted` ответа к предыдущему
стоп-уроку; `new`, `viewed`, `declined`, неизвестный или будущий статус не
открывают следующий. Поддержан тип условия «задание к этому уроку»;
остальные варианты закрыты. Отмеченный «доступен независимо от стоп-уроков»
урок обходит только эту преграду, не покупку и не расписание. Основание:
[стоп-уроки GetCourse](https://getcourse.ru/blog/1171272).

## Содержимое и ограничения

Текстовые блоки доступны через отдельный защищённый читатель. Изображения,
PDF и аудио пока представлены описаниями; исходные файлы не выданы. Задания
не выполняются в приложении, комментарии и ответы учениц не переносятся.
Платные видео закрыты: поддерживаемое встраивание GetCourse не подтверждено.
По выбору пользователя остаётся дождаться ответа GetCourse; переходы на
GetCourse и внешняя кнопка видео не добавляются, видеофайлы не переносятся.
Три ранее согласованных бесплатных видео сохраняют своё прежнее поведение.

## Подключение и проверка

Ключи остаются в `/etc/wep-pril/getcourse-tech.env` с правами root 0600;
`auth.env` и ключ регистрации не заменяются. Миграция
`backend/auth/course-checks-migration.sql` добавляет таблицу без изменения
аккаунтов, сессий или каталога SQLite; основной `auth/migrate.mjs` также
применяет её идемпотентно. Путь к SQLite задаётся необязательным
`COURSE_DATABASE_PATH`, по умолчанию `/opt/wep_pril/data/articles.sqlite` на
сервере. Служба входа открывает базу read-only и закрывает при остановке.

Локальный импорт фактической политики завершился для всех 122 разделов и 749
уроков. Синтетический сценарий с покупками всех 28 продуктов, всеми 122 ID
тренингов и принятыми стоп-заданиями открыл 636 уникальных уроков и 3919
исходных блоков текста; текст сверен с источником, адресов и ID видео в
ответах нет. Остальные 113 уроков закрыты консервативными правилами для
скрытых разделов, неизвестных покупок дочерних продуктов, групп и других
неподдержанных условий. Это локальная проверка на искусственных правах, не
результат проверки реальной оплаченной ученицы.

Реальный `getLessonStatuses` ответил успешно для оплаченного и неоплаченного
контрольных кандидатов, но в обоих случаях статусов заданий было 0.
Разблокировка по `accepted` подтверждена схемой и синтетическими тестами,
живой успешный пример стоп-урока пока не проверен.

Локальные тесты `backend/test/course-checks.test.mjs`,
`course-entitlements.test.mjs`, `course-materials.test.mjs` и
`auth-courses.test.mjs` проверяют границу пяти минут, старый снимок,
покупку конкретного продукта, дочерние условия, стоп-уроки, закрытый видео-
и медиаконтент, ошибки и HTTP-проверку сессии/профиля. Они не доказывают
нагрузку 1000 пользователей, лимиты Tech API или реальное поведение
оплаченной ученицы на опубликованном сайте. Всего прошли 77 backend-тестов.

Предыдущий выпуск только слоя проверки свежести был проверен на Timeweb:
закрытая копия PostgreSQL, миграция, контрольное чтение, повторное
использование результата до истечения срока и внешний 401 без сессии.
Это **история предыдущего этапа**; публикация новых маршрутов текстов и их
проверка на рабочем HTTPS описываются отдельно после завершения выпуска.

## Публикация текстов и живые проверки, 23 октября

На Timeweb опубликованы маршруты и существующие страницы курсов. В SQLite
добавлена только `course_delivery_policy` для 122 разделов и 749 уроков;
отпечатки статей (126), недельных записей (129), предложений (3), продуктов
(30), состава (36) и всех исходных черновиков (749) до/после совпали.
Приватная резервная SQLite и прежние файлы сохранены в
`/root/wep-pril-course-materials-20261023/release/before/`.

Служба `wep-pril-auth` получила дополнительную группу `wep-pril` для чтения
существующего файла SQLite (root:wep-pril 0640, каталог без записи для группы).
Соединение Node.js read-only. Перезапущена только служба входа; служба контента,
карточки GetCourse, покупки и `auth.env` не менялись. Оба ключа Tech API
загружены из прежнего закрытого файла; ключ регистрации сохранён.

Серверная проверка нового модуля с реальными GET-ответами GetCourse дала
оплаченному контрольному кандидату 2 продукта, в том числе 104 разрешённых
урока основного Экспресс. Пример из 22 блоков совпал с исходным текстом и не

403 на прямой вызов урока. Проверка не создавала прав и не использовала вход

полный браузерный сценарий.

Через действующую бесплатную сессию на рабочем HTTPS проверены пустые «Мои
курсы», отказ по прямой ссылке платного урока без текстовых/медиаблоков и
обычная статья `pregnancy-001`. Без сессии все три маршрута, course-check и
новые JS/CSS дают 401 и no-store; страница курсов направляет ко входу.

В Chrome на изолированных вымышленных данных проверены переходы курс →
разделы → текст, таблица, закрытое видео, ошибки 401/403/404/503, повтор,
истечение проверки с неудачным обновлением и возврат после отзыва доступа.
На ширинах 320/390/500/1440 переполнения страницы нет; на ПК колонка до 500 px.
Пять дополнительных локальных проверок жизненного цикла включают истечение
во время отрисовки; длительная отрисовка не продлевает показ материала.
Оплаченная сессия реальной ученицы и живой accepted-стоп-урок остаются
непроверенными. Платное видео закрыто, как согласовано.
