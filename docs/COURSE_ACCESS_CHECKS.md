# Проверка GetCourse на пять минут

23 октября 2026 пользователь согласовал: при открытии курса или урока
использовать результат не дольше пяти минут. Если результат устарел,
а GetCourse недоступен, платный материал временно закрывается.

## Реализованный серверный этап

`backend/auth/course-checks.mjs` читает покупки и доступные тренинги через
проверенный Tech API клиент. ID школы берётся из связи `auth_users` текущей
сессии. В `course_access_checks` отдельной PostgreSQL хранится один последний
результат на пользователя: ID продуктов и тренингов, периоды и флаги покупок.
Email, суммы, названия тренингов и произвольные поля ответа не сохраняются.

Срок отсчитывается от начала чтения, составляет максимум 300000 мс и
дополнительно ограничен CHECK в PostgreSQL. В момент точного истечения
результат уже недействителен. Повторный вход, новый объект сервиса, ошибка
GetCourse или БД не продлевают срок. Пустой успешный ответ заменяет прежние
покупки, а ошибка не становится подтверждением отсутствия покупок.

Параллельные запросы одной ученицы объединяются; общая аренда в PostgreSQL
не позволяет двум экземплярам одновременно обновлять одну карточку.
Аренда длится 30 секунд, после ошибки действует короткая граница повторной
попытки. Старая аренда не может перезаписать новый результат. Нет массовой
синхронизации всей школы, фонового обхода неактивных учениц или автоматических
повторов к GetCourse. Частота проверок определяется открытиями материалов;
в активном платном экране обновление должно происходить и по истечении срока.
Такого экрана выдачи платных материалов пока нет.

`GET /api/auth/course-check` требует действующую сессию и заполненный профиль.
Он возвращает только `verification: "current"`, `checkedAt` и `expiresAt`.
ID ученицы и GetCourse, покупки, адреса видео и тексты не выдаются. Параметры
URL не принимаются: нельзя запросить проверку другого пользователя.
Без входа — 401, без профиля — 403, при неуспехе проверки — 503 с `no-store`.
Сбой проверки курсов не завершает обычную сессию и не закрывает бесплатные
материалы. Перед любой будущей платной выдачей сервер должен вызывать
`requireCurrent(userId)`, затем отдельно проверять право конкретного продукта
и урока. В интерфейсе платного просмотра потребуется закрывать содержимое
к `expiresAt`, в том числе при потере сети или возвращении к вкладке.

## Подключение

Ключи остаются в `/etc/wep-pril/getcourse-tech.env`, root 0600. Systemd читает
файл через отдельный drop-in [wep-pril-auth-tech.conf](../deploy/wep-pril-auth-tech.conf).
`auth.env` и ключ регистрации не заменяются. Миграция
`backend/auth/course-checks-migration.sql` создаёт только новую таблицу,
не меняя прежние аккаунты, сессии или каталог SQLite. Основной `auth/migrate.mjs`
также включает эту идемпотентную миграцию. Если Tech API не настроен,
проверка курсов закрыта, обычный вход продолжает работать.
На действующем сервере миграция применяется от существующего владельца
`wep_pril_auth_owner`; рабочая роль приложения сохраняет только прежние
права чтения и записи, без разрешения создавать таблицы.

## Границы

Свежий результат — только доказательства для следующей проверки прав.
Он не открывает весь тариф, не означает разрешение каждого дочернего урока
и не превращает `is_payed` в надёжное условие оплаты. На реальной оплаченной
покупке этот флаг равнялся 0. Отмены, ручное отключение, заморозка и условия
дочерних тренингов требуют отдельной сверки. Все 749 черновиков остаются
`delivery_status='unavailable'`, маршрутов выдачи текстов или платных видео
нет. Три согласованных бесплатных видео сохраняют прежнее поведение.

Проверки `backend/test/course-checks.test.mjs`: точная граница пяти минут,
сбой и восстановление, отсутствие продления при повторных запросах,
сохранение после перезапуска, пустая новая покупка, частичный сбой API,
привязка к ученице, гонки аренды, медленное чтение, ограничения БД,
неавторизованные запросы и отсутствие сырых данных в ответе.
Это функциональная проверка, а не подтверждение нагрузки 1000 пользователей
или лимитов Tech API GetCourse.

Выпуск проверен на Timeweb: создана закрытая резервная копия PostgreSQL,
применена миграция от существующего владельца БД, перезапущена только служба
входа. `auth.env` и ключ регистрации не менялись. На собственной контрольной
карточке выполнены два чтения GetCourse, повтор из нового объекта сервиса
использовал сохранённый результат без дополнительных чтений; срок — 300000 мс.
В действующем входе Chrome запрос проверки вернул только три заявленных поля.
Без сессии внешний HTTPS возвращает 401 и `Cache-Control: no-store`.
