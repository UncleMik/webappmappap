# admin-notifications contract

## Settings — stable contract
`createGamificationSettings({pool,clock})` from backend/auth/gamification-settings.mjs returns async `get()` (fresh validated snapshot) and `publicSettings()`.
Snapshot: `enabled`, `medicalApproved` (derived from explicit approval, never enabled), `aiBudgetApproved`, `features` {stars,daily,weekLocks,peekNextWeek,aiPacks,myths,quests,capsule,games,notifications,push}, `rewards` {welcome,checkin,surprise,mythAnswer,mythCorrect,article,video,courseLesson,weekComplete,poll,pollMajority,clubMessage,kicks,quest,firstKick,capsule,trimester}, `limits` {freeDaily,courseDaily}, `prices` {peekNextWeek,aiPackFree,aiPackCourse}, `ai` {freeDaily,courseDaily,freePack,coursePack,freePurchases,coursePurchases,freePaidDaily,coursePaidDaily}. Defaults from RULES; all feature flags false. `medicalApproved=false`, `aiBudgetApproved=false` initially. Consumers must separately gate medical content by item approval and AI packs by budget approval.

## Admin
`createGamificationAdmin({pool,admin,settings,clock})`: `state(token,account)`, `updateSettings(token,account,{patch,reason})`, `saveContent(token,account,{id,kind,body,medical,revision})`, `approveContent(token,account,{id,revision,evidence})`, `approveGate(token,account,{gate,approved,evidence})`, `history(token,account)`. All check admin.session role owner and account. Edits reset approval; medical default true; explicit approval with evidence only owner (the only currently authorized role). No editor rights added. Audit actor/time/before/after stored atomically.
Admin HTTP wiring owned here: optional `gamificationAdmin` argument to createAdminHttp. GET /api/admin/gamification, /api/admin/gamification/history; POST /api/admin/gamification/settings, /content, /approve-content, /approve-gate.

## Notifications
`createGamificationNotifications({pool,service,settings,clock,pushTransport,pushPublicKey})`.
Authenticated methods: `list(token,account)`, `read(token,account,{ids})`, `preferences(token,account,patch?)`, `subscribe(token,account,subscription)`, `unsubscribe(token,account,{endpoint})`, `visit(token,account)`, `claimPresentation(token,account,{kind,sessionId})` (kind hint/celebration).
Transactional internal `enqueue(client,{userId,key,type,title,body,url,babyRelated,medical,priority,availableAt})`; unique user/key, no stars-only notifications. Types new_week,capsule,quest,poll_results,week_almost,daily,feature,celebration. `processQueue({limit=100})` opt-in worker; no production transport configured by default. One push/local day, quiet hours at least 21–09 local, priority order above; new_week suppresses other candidates that day; daily skipped after local visit. No chat read operations. Preferences pauseBaby, timezone, pushEnabled, types, quietStart, quietEnd. Push delivery uses VAPID standard browser push, no new paid provider.
User HTTP hooks needed from access-ai: GET /api/auth/notifications; POST /api/auth/notifications/read, /preferences, /subscribe, /unsubscribe, /visit, /presentation. GET preferences optional via method. Public key returned in list. Pass bodies to corresponding methods. Existing session/origin/account gates retained.
Main hooks for orchestrator: apply gamification-admin-migration.sql after auth/admin migrations; construct settings, notifications, gamificationAdmin; pass settings to wallet/daily, notifications to daily, gamificationAdmin to createAdminHttp. Worker processQueue timer must only be enabled explicitly with VAPID config. Env proposal GAMIFICATION_PUSH_PUBLIC_KEY, GAMIFICATION_PUSH_PRIVATE_KEY, GAMIFICATION_PUSH_SUBJECT; keep secrets out of Git. No production sends in development.

Additional helper `settings.get(client)` accepts optional transaction client.
