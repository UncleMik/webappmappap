# access-ai — готово к интеграции

Владелец: ai-chat.mjs, http.mjs, server.mjs, profile.mjs; новые stars-ai.mjs, stars-access.mjs, stars-ai-migration.sql и собственные тесты. Чужие файлы не меняю.

- createStarsAi({pool,clock}) предоставляет quota(client,{userId,tier,now}), reserve(client,context,{requestId}), refund(client,{userId,requestId}). Все вызовы из транзакции с блокировкой auth_users; единый купленный запас wallet будет указан после чтения wallet handoff. Использование привязано к Москве, free first, любое обращение=1 (с 2026-11-13), refund однократен.
- createStarsAccess({stars, catalog}) предоставляет context(token,account), canWeek(context,week), assertWeek(context,week), filter(context,items). Legacy и выключенный rollout сохраняют доступ; календарь исключён. HTTP и Lara используют один gate.
- createAuthServer получает дополнительные необязательные зависимости stars, starsAccess, gamification, gamificationNotifications. Новые routes сохраняют origin/session/account проверки существующего сервера. Точные notification routes будут добавлены по handoff владельца.

Оркестратору: подключить новые фабрики и миграцию из main/config/migrate; server wiring уточню после реализации. Вопросы медицинского утверждения/бюджета повторно не задаю. Production не меняю.

## Уточнение AI (19:35)
Единственный stock: auth_stars_ai_credits.balance (таблица wallet). createStarsAi({pool,clock}) -> quota(client,{userId,tier,now}), reserve(client,{userId,tier,now},{requestId}), refund(client,{userId,requestId}). tier=free/course. reserve/refund вызываются только внутри transaction(); первым блокируется auth_users.id FOR UPDATE, затем stock/daily/reservation. Wallet обязан первым брать тот же auth_users lock, до auth_stars_wallet/stock. Покупка и расход сериализуются этим общим lock. AI-specific миграция создаёт только usage/reservations, не stock.
quota: старые limit/used/remaining означают бесплатную квоту 5/30; добавлены freeRemaining, paidRemaining (весь бессрочный stock), paidUsed, paidDailyRemaining, totalRemaining (доступно сейчас) и maximum=11/40. Старые потребители совместимы; новый UI использует totalRemaining. Дневные usage не привязаны к tier, смена курса не создаёт вторую квоту. failed возвращает и free, и paid по сохранённой исходной московской дате ровно один раз.
Оркестратору: starsAi передать в createAiChat. Для включённой новой экономики это обязательно, при отсутствии зависимости сохранён старый AI-контракт. Применить stars-ai-migration.sql после старых AI migrations и wallet migration.

## Контракт недельной выдачи
createStarsAccess({stars}) -> context(token,account), canWeek(ctx,week), assertWeek(ctx,week), filter(ctx,items), weekly(ctx,data), videoWeek(position).
Контекст wallet должен содержать settings.enabled/settings.features.weekLocks и legacy=false ТОЛЬКО для новых/проверенных аккаунтов. При unknown legacy сохраняем доступ. Бессрочные покупки читаются из auth_stars_week_purchases. Дополнительные подтверждённые старые открытия можно передать ctx.preservedWeeks.
При включённых замках GET /api/weekly-content сохраняет полный calendar/calendarNotes, но mom/baby содержит только разрешённые недели. Новое поле access={currentWeek,availableWeeks}. Frontend: убрать требование полноты всех 42 mom/baby; отправлять X-Webpril-Account к article/weekly API, не сохранять полный общий corpus между аккаунтами. Закрытые статьи не выдаются в /api/articles, прямой /api/articles/:id даёт week_locked. Видео источник/file/cover и HEAD используют тот же gate.
Оркестратору: article server createArticleServer(db,origin,{starsAccess}) требует эту зависимость и доступ к сессии через stars; конфигурация standalone entrypoint будет описана ниже. Nginx должен передавать Cookie и X-Webpril-Account на article backend, не кэшировать ответы и исключить любые статические полные JSON с контентом. Платные курсы через courseMaterials не ограничиваются неделями и при ошибках остаются закрытыми по прежним правилам.

## Продолжение: актуальный контракт (12 ноября)
- `createStarsAi({pool,settings,clock})`: get(client) получает реальные ai.freeDaily/courseDaily и freePaidDaily/coursePaidDaily. Купленный запас расходуется только при enabled + features.aiPacks + aiBudgetApproved. При отключении банк не очищается; лимит купленного расхода становится 0. Все арифметические даты нормализованы, clock может вернуть Date.
- Возврат pending до миграции (без reservation): при атомарном pending→failed возвращается одна старая free единица по accepted_at. Новые reservations возвращают исходный free/paid расход, уже refunded не возвращаются повторно.
- Standalone `backend/server.mjs` теперь использует `createLocalStarsAccess` и **не импортирует auth/main**. Env `AUTH_WEEKLY_ACCESS_URL` по умолчанию `http://127.0.0.1:3001/api/auth/internal/weekly-access`. Необязательный `AUTH_ORIGIN` для CORS. Узкий auth GET endpoint принимает только loopback peer, Cookie и X-Webpril-Account, возвращает только accountId/currentWeek/enforced/legacy/purchasedWeeks/preservedWeeks. Ошибка политики закрывает статьи. Nginx должен запретить внешний `/api/auth/internal/`, даже если reverse proxy сам loopback, и передавать Cookie/Account к article API. Нельзя отдавать полные JSON статикой или кэшировать account-specific corpus.
- Новый `ai-urgent.mjs`: `createAiUrgent({pool,settings}).evaluate({text,tags?})`, reusable daily для тревожных тегов. По умолчанию выключен. Требует enabled + medicalApproved и конкретный approved medical content `urgent-help` с evidence/approved_by/approved_at. `body={paragraphs:[...]}`: полный urgent_help_source 2585–2607. Admin/daily: добавьте этот источник в доступный редактору каталог, чтобы владелец мог утвердить экран и словарь вместе. Без него экран не включается.
- `createAiChat` теперь принимает settings (main уже передаёт) и необязательный urgent для unit fixtures. POST messages возвращает `{accountId,requestId,status:'urgent',urgent:{contentId,revision,title,body,reassurance,actions,free:true,continueToken:{expires,signature}},quota}` без записи в AI history и без расхода. UI показывает статичный экран; кнопка «Это не срочно, продолжить» повторяет **те же requestId/text/attachment/conversationId** с `urgentContinue=urgent.continueToken`. Token связан с аккаунтом, текстом/файлом, беседой и редакцией, действует 10 минут. Каждое новое сообщение проверяется; произвольный boolean continue не обходит проверку. Обычная отправка после continue использует прежнюю идемпотентную reservation.
- Встроенные video/cover HTML-запросы не умеют X-Webpril-Account. Пока gate требует header на всех media URL; frontend/root должны проверить фактическую подачу header или согласовать передачу expected account для file/cover без потери account isolation. Не считать браузерный playback проверенным.

Проверки в работе. Сеть, npm, HTTP/socket/browser и production здесь не запускаются по поручению оркестратора.

## Native media — исправленный контракт
GET `/api/auth/videos/:id` возвращает `{source:'/api/auth/videos/:id/file?account=<uuid>',cover:'/api/auth/videos/:id/cover?account=<uuid>'}` после session/account/week checks. Native file/cover GET+HEAD принимают expected account из X-Webpril-Account или единственного query `account=<uuid>`; UUID сверяется с живой сессией и недельной политикой, чужой UUID даёт account_changed. Без header/query при включённом gate доступ закрыт. Это не токен и не право доступа. Frontend: для src/poster/cover использовать полученные URL либо добавлять только `account=account.id` по тому же правилу к cover URL; после смены аккаунта сбрасывать плеер. Предыдущую заметку о session-only считать заменённой этим контрактом.
При выключенном runtime local policy endpoint всё равно проверяет сессию/аккаунт/профиль и возвращает enforced=false без запуска wallet. Старый доступ к статьям сохраняется; поломка auth endpoint остаётся fail closed.
