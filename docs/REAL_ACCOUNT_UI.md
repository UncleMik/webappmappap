# Настоящий аккаунт вместо демо-профиля

Дополнение 19 октября: реализован обязательный [рабочий онбординг](ONBOARDING.md)
с серверным профилем. Описание прежнего этапа ниже сохраняется как история.

19 октября пользователь поручил убрать демо-аккаунт и уточнил:
«Сначала убрать демо, заполнение позже».

## Сценарий

Вход и регистрация остаются одной формой email → код. После подтверждения
нового адреса сервер создаёт аккаунт с постоянным ID и связывает GetCourse;
повторный вход возвращает прежний аккаунт этого адреса. Разделение аккаунтов
уже выполняется сервером, отдельная регистрация с паролем не добавляется.
Для покупки на другой email остаётся согласованный путь через поддержку.

Профиль и «Личные данные» показывают email только из действующей серверной
сессии. Имя, фото, фамилия, город, дата рождения и срок не подставляются
из примера. До подключения заполнения профиля они пустые. На главной —
нейтральное приветствие и значок аккаунта. Процент заполнения, учебный
прогресс и уведомления из демонстрационного профиля убраны.
В ИИ-чате убраны имя примера, фиктивный срок и прежний пример переписки;
подключение самого помощника остаётся следующим этапом.

Личный срок в 27 недель и 4 дня, отсчёт 82 дней и отметка «Сейчас» в
календаре убраны. Материалы по неделям и выбор недели сохранены; стартовая
27-я неделя в просмотре материалов не означает личный срок пользовательницы.
Определение срока по ПДР остаётся следующим этапом.

«Мои курсы» показывает, что информация пока недоступна. Это не утверждение
об отсутствии покупок: серверная синхронизация покупок и учебного прогресса
ещё не подключена. Запись `webpril.demoCourseAccess` в браузере больше не
включает «Премиум», не выдаёт доступ и не подменяет реальную покупку.
Каталог сохранён; тестовая выдача курсов отключена.

Выход из профиля и «Личных данных» обращается к серверу и открывает форму
входа во всём окне. Тем самым старые секции приложения, сохранённые во
внутренних iframe, не остаются экраном прежнего аккаунта. Возврат из
истории браузера и фокус страницы перепроверяют сессию; ошибка проверки
не оставляет на экране прежний email.

## Проверки и размещение

- `node --test tools/test-account-ui.mjs` — восемь проверок: настоящий
  email, новый/прежний адрес, анонимный вход, ошибка перепроверки, успешный
  и неуспешный выход, поздний ответ старого запроса, отказ демо-покупки.
- Повторно пройдены четыре проверки используемого издателя файлов:
  публикация/повтор, повреждённый источник, неизвестная прежняя версия,
  откат при ошибке итоговой проверки.
- [publish-account-ui.py](../deploy/publish-account-ui.py) меняет только
  16 перечисленных файлов интерфейса. До записи проверяются все старые
  и новые SHA-256, создаётся закрытая резервная копия. Файлы данных,
  ключи, Nginx и службы не меняются; перезапуска службы нет.
- Файлы отдельной интеграции трёх видео, включая её `login.js`,
  `login.html` и `journey.html`, этим выпуском не заменяются.

Статус: изменения опубликованы в GitHub Pages и проверены в Chrome.
Профиль и «Личные данные» показывают пустые значения без демо-имени;
«Мои курсы» не показывает «Премиум», ИИ-экран не содержит прежней примерной
переписки. При 390×844 ширина документа 390 px, горизонтальной прокрутки
нет. Календарь открывается, выбор 26-й недели и переход к её материалам
работают; фиктивной отметки текущей недели нет. Эмуляция сброшена.

На Timeweb пользователь применил выпуск `d6596f4` под root и получил
`ACCOUNT_UI_PUBLISHED_OK` и `AUTH_AND_MATERIALS_HEALTH_OK; NO_SERVICE_RESTART`.
Все 16 файлов рабочего HTTPS независимо сверены с закреплёнными SHA-256.
Путь закрытой резервной копии сохранён вне Git в `output/auth-qa/`.

На рабочем сайте в Chrome проверены вход по настоящему коду в прежний
аккаунт, его email в профиле и «Личных данных», сохранение входа после
обновления обеих страниц и переходов между ними. Проверены выход из
«Личных данных» и выход из профиля: форма входа открывается во всём окне,
сервер после выхода возвращает `authenticated=false`, `user=null`.
Новую карточку GetCourse в этой проверке не создавали; сценарий новой
регистрации проверялся в предыдущем этапе входа и здесь не изменён.
Письмо с кодом доставлено во входящие Gmail; SPF/DKIM/DMARC — pass.
Публичные API входа и материалов отвечают `200`, доступно 126 статей.

При попытках повторной мобильной эмуляции на рабочем сайте инструмент
браузера не применил размер; мобильная проверка 390×844 относится к
GitHub Pages с теми же 16 файлами. Во время этой серии проверок один раз
обнаружена завершённая сессия без установленной причины. Повторный вход,
обновления страниц и переходы при обычном размере прошли без повторения
сброса; намеренный выход отдельно подтверждён сервером. Полную проверку
длительности сессий и разных устройств это не заменяет.

## Следующие этапы

Рабочее заполнение и серверное хранение профиля, ПДР, учебного прогресса
и личных записей, а также выдача прав по покупкам GetCourse не входят
в это удаление демо-данных. Личные инструменты пока используют локальное хранилище прежнего
прототипа; привязка их записей к ID аккаунта и серверу нужна отдельно.
Полную синхронизацию между устройствами эта правка не подтверждает.
