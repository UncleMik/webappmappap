# Временная проверка входа через сайт

19 октября 2026 года полный сценарий проверен на рабочем HTTPS в Chrome
с собственной контрольной почтой. Использовался тест по одному IP с
15-минутным таймером. После проверки автоматическое закрытие подтверждено:
вход отвечает `503 auth_unavailable`, API материалов — `200`, 126 статей.
После этого пользователь согласовал [постоянное включение](AUTH_PUBLIC_ENABLE.md).
Постоянный вход уже включён и повторно проверен; результат описывается
отдельно. Этот документ фиксирует предшествовавший временный тест.

## Подтверждённый результат

- Настоящий код Unisender доставлен во «Входящие» Gmail; SPF/DKIM/DMARC —
  pass, ссылка отписки сохранена. Код не печатался и не записывался в файлы.
- После подтверждения создана одна карточка GetCourse с двумя метками
  приложения. Сессия появилась, сохранилась после обновления страницы.
- Приветствия GetCourse для этой карточки нет в её журнале и Gmail.
  Обе email-категории автоматически сняты без ручного редактирования.
- Повторный вход выполнен по новому коду на тот же email: дубля карточки
  GetCourse нет. Выход проверен и на странице входа, и в профиле;
  после каждого сервер вернул `authenticated=false`, `user=null`.
- На Timeweb отсутствовали блок аккаунта в профиле и его JS-модуль.
  Пользователь выполнил подготовленную публикацию только `profile.html`
  и `account-access.js` из закреплённого коммита с проверкой SHA-256
  и резервной копией. Из профиля проверены переход ко входу, показ email
  текущего аккаунта и выход.
- Профиль дополнительно просмотрен при эмуляции 390×844: блок аккаунта
  видим, ширина документа 390, горизонтальной прокрутки нет. Основной
  сценарий с настоящими кодами проверялся в настольном Chrome; реальные
  мобильные браузеры и PWA этим не проверены. Эмуляция сброшена.

Согласия, покупки, роли и платные права не менялись. Имя, ПДР и другие
демонстрационные данные профиля ещё не подключены к рабочему аккаунту.
Проверка двух категорий не заменяет аудит остальных процессов школы.
Резервное восстановление, документы, другие почтовики и целевая нагрузка
в 1000 активных пользователей остаются отдельными условиями запуска.

Предыдущие отказы на поиске отметки браузера происходили до включения
входа. Успешный запуск получен после обновления отмеченной страницы
пользователем непосредственно перед серверной командой.

## Что делает серверный скрипт

[check-auth-browser.py](../deploy/check-auth-browser.py) запускается вручную
под root через консоль Timeweb. Прежний запрет браузерного доступа агента
к консоли не обходится.

1. Проверяет закрытый режим действующей службы, доступность конфигурации,
   права `0600` файла секретов и SHA-256 установленного адаптера GetCourse.
2. По свежему отмеченному GET-запросу из браузера находит его IP в журнале
   собственного Nginx. Метка запроса не является паролем. IP в чат не выводится.
3. Сохраняет закрытую копию конфигурации Nginx, ограничивает только
   `/api/auth/` одним найденным IP, выполняет `nginx -t` и проверяет запрет
   с loopback через HTTPS с действительной проверкой сертификата.
   После reload повторяет запрос до 20 раз с паузой 250 мс, пока не получит
   `403`: старые рабочие процессы могут завершаться после команды reload.
   До подтверждённого запрета временное включение входа не создаётся;
   ошибки TLS или соединения не обходятся. Это исправляет воспроизведённый
   локально отказ при задержке reload, но не доказывает причину старого
   серверного сбоя. Порядок reload описан в [документации Nginx](https://nginx.org/en/docs/control.html).
   Маршруты статей и остальных материалов сохраняются.
4. Сначала ставит и проверяет таймер автоматического закрытия через 15 минут.
   Затем временно включает настоящую службу с дополнительным EnvironmentFile
   через systemd в `/run`. Постоянный `/etc/wep-pril/auth.env`, ключи,
   пароли, HMAC, схема базы и код службы не меняются.
5. Проверяет ответ анонимной сессии на loopback. При успехе печатает
   `AUTH_BROWSER_CHECK_READY_15_MINUTES` и строку `CLOSE_COMMAND=…`.

Временные файлы:

- `/run/wep-pril-auth-browser-check.env` — только флаг теста, `0600`.
- `/run/systemd/system/wep-pril-auth.service.d/90-browser-check.conf` —
  добавочный EnvironmentFile; после перезагрузки `/run` не сохраняется.
- `/root/wep-pril-auth-browser-check/<номер>/` — закрытая резервная копия
  Nginx и состояние теста с IP. Не копировать в Git или публичный отчёт.

Остальным IP служба входа на время теста отвечает `403`. Постоянная
конфигурация остаётся выключенной. На время проверки не публиковать
конфигурацию Timeweb и не менять подключение/VPN браузера: это ограниченный
операционный тест, а не включение входа для учеников.

## Порядок проверки

Перед серверной командой пользователь открывает или обновляет уникальный
GET-запрос в том же Chrome, которым агент затем будет проверять вход.
Открытия страницы агентом до передачи инструкции недостаточно, если
прошло больше 20 минут. После обновления страницы команду нужно выполнять
сразу. Команда первой установки загружает скрипт из закреплённого Git-коммита, сверяет
его SHA-256, сохраняет в закрытый файл root и запускает. Источник запроса
должен быть не старше 20 минут. Точный адрес и метка находятся в текущей
локальной команде, а не в этом общем документе.

После `AUTH_BROWSER_CHECK_READY_15_MINUTES` проверяем:

- вход на `https://app.legkie-rody.ru/login.html` с контрольным email;
- доставку настоящего кода Unisender и подтверждение почты;
- новую карточку GetCourse с метками приложения и без дубля;
- отсутствие приветствия GetCourse и последующее снятие email-категорий;
- появление подтверждённой сессии, сохранение после обновления и выход.

Коды, cookie и секреты не выводим в отчёт. Периодический процесс GetCourse
может выполняться с [задержкой 5–15 минут](https://getcourse.ru/blog/275873).
Тест не доказывает изоляцию от всех остальных процессов школы, готовность
документов, работу всех браузеров или нагрузку в 1000 активных пользователей.

## Закрытие и восстановление

Для раннего завершения выполняется выведенная строка `CLOSE_COMMAND`
(без префикса `CLOSE_COMMAND=`). Иначе её запускает серверный таймер.
Скрипт удаляет только собственный временный переключатель, перечитывает
systemd и перезапускает закрытую службу. Затем удаляет только свой IP-блок
из текущего Nginx, сохраняя независимые изменения за время теста.
После успешного закрытия печатается `AUTH_BROWSER_CHECK_CLOSED`.

При ошибке закрытия IP-ограничение остаётся, слушатель останавливается.
Нужно проверить состояние под root перед повторной попыткой. Текст ошибки
не включает секреты. Новая версия печатает `AT=функция:строка`, фиксированный
тип отказа и числовой код завершения команды. Текст исключений, аргументы
команд и их stderr/stdout не печатаются; при ошибке отката сохраняется
диагностика исходной ошибки. Существующие пользовательские карточки, сессии и
покупки тестовый скрипт не удаляет.

После закрытия снаружи нужно подтвердить ожидаемый закрытый ответ входа
и доступность материалов. Только выполненный вход, сохранение и выход
можно отмечать как результат проверки.

## Проверено локально

13 проверок в [test_check_auth_browser.py](../deploy/test_check_auth_browser.py)
прошли на временной файловой системе с подменёнными системными командами.
Они проверяют порядок установки IP-ограничения и таймера, отказы проверки
Nginx/таймера/службы, закрытие, сохранение независимых правок и требования
к свежему запросу браузера, задержку применения reload, отказ проверки
сертификата и отсутствие секретов в сообщениях ошибок. Реальные Nginx,
systemd, почта и GetCourse в этих тестах не запускались. Полный сценарий на рабочем HTTPS затем выполнен в ограниченном
тестовом режиме; его результат и границы приведены в начале документа.
