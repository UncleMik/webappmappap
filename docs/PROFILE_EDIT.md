## Границы

Редактируются имя (обязательно), фамилия, дата рождения пользовательницы,
город и телефон (необязательно, можно очистить), этап, срок/ПДР или дата
рождения малыша, цели и фото. Цели — прежние семь вариантов каждой ветки,
хотя бы одна обязательна. Переход к материнству требует подтверждения
рождения. По наступлению ПДР этап автоматически не меняется.

Шестерёнка открывает настройки с переходом к данным и целям. Русский язык,
Москва (UTC+3) и вход по коду на email показаны как сведения. Выбор иных
языков, поясов и способов входа не реализуется. Смена email — через поддержку;
реальные контакты поддержки остаются отдельной задачей.

Чаты, события, уведомления, обучение, поддержка и юридические документы в
этот выпуск не входят. Дизайн и основная навигация сохраняются.

## Данные и API

Расширяется существующий JSONB `auth_users.profile` отдельной PostgreSQL.
В GetCourse личные поля не передаются, email и покупки не меняются.

- POST `/api/auth/profile-edit`: `{accountId, changes, confirmMother?}`.
  `changes` — только изменённые поля: `name`, `surname`, `birthday`, `city`,
  `phone`, `stage`, `dueDate`, `birthDate`, `goals`. Имя — до 80 символов,
  фамилия — до 80, город — до 100; телефон — международный номер с `+`.
- POST `/api/auth/profile` остаётся первой анкетой. Завершённый профиль
  не перезаписывается этим маршрутом; возвращается 409.
- POST `/api/auth/profile-photo`: `{accountId, photo}` — base64 JPEG либо
  `null` для удаления. Ответ обоих новых POST содержит актуальный `user`.
- GET `/api/auth/profile-photo?v=<photoVersion>` возвращает только своё фото
  по действующей сессии с `private, no-store`. Старые версии не выдаются.

ID владельца берётся из сессии, `accountId` дополнительно защищает от
отправки старой формы после смены аккаунта. На сервере проверяются Origin,
разрешённые поля, календарные даты, срок и цели. Частичное изменение имени
не требует заново подтверждать уже сохранённую ПДР, даже после 42 недель.

Каждое поле открывает панель с «Сохранить» и «Отмена». Ошибка сохранения
сохраняет введённые данные. После успешного ответа разделы и другие вкладки
получают сигнал и перечитывают серверную сессию. Личные данные не передаются
между вкладками через localStorage; BroadcastChannel содержит только сигнал.

## Фото и резервные копии

Браузер принимает JPG/PNG/WebP до 8 МиБ, уменьшает до 512 пикселей по
длинной стороне и пересохраняет JPEG без исходных метаданных. Сервер
проверяет JPEG, размер до 350 КиБ и геометрию до 512×512.

Файлы лежат вне публичного каталога:
`/var/lib/wep-pril-auth/profile-photos/`, права каталога 0700, файла 0600.
`StateDirectory=wep-pril-auth` разрешает запись только в каталог состояния
службы. При успешной замене/удалении прежний файл удаляется.

Ежедневная копия включает фото в `uploads.tar.gz` под
`uploads/private-profile-photos/`. При восстановлении эти файлы нужно
вернуть в `/var/lib/wep-pril-auth/profile-photos/` с владельцем
`wep-pril-auth:wep-pril-auth` и закрытыми правами, а не в публичные uploads.
База восстанавливается из того же комплекта копии. Издатель сохраняет
проверенную копию и прежние файлы до обновления; откат кода не откатывает
новые действия пользовательниц в базе.
