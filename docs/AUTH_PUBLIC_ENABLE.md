# Постоянный публичный вход

Основание: 19 октября 2026 года пользователь поручил «СДЕЛАЙ публичный
вход рабочим» после успешной проверки настоящих писем, GetCourse и сессий.
Это согласование постоянного включения ранее реализованного входа.

Статус на 19 октября 2026 года: постоянный публичный вход включён.
Пользователь выполнил команду под root; скрипт подтвердил
`AUTH_PUBLIC_ENABLED_OK`, резервную копию, автозапуск и отсутствие
временного ограничения IP и таймера закрытия.

Снаружи GET сессии возвращает `200` и анонимное состояние. Через Chrome
пройден новый настоящий код → вход в прежний аккаунт → обновление страницы
с сохранением входа → профиль с email → выход с подтверждённой анонимной
сессией. GetCourse сохранил одну прежнюю карточку; две категории рассылок
сняты. В Gmail на контрольный адрес найдены только три запрошенных за день
письма с кодами, без приветствия школы. Последнее письмо — «Входящие»,
SPF/DKIM/DMARC pass, отписка сохранена. Материалы — `200`, 126 статей.
Проверки в этом разделе относятся к действующему Timeweb; собственно
перезагрузка сервера не выполнялась.

## Включение

[enable-auth-public.py](../deploy/enable-auth-public.py) выполняется под root
на действующем Timeweb. Он использует уже установленный модуль ограниченной
проверки с проверкой его SHA-256. Сам временный тест не запускается.

- Проверяет, что прошлые тесты закрыты, временных переключателей,
  ограничений IP и активного таймера закрытия нет.
- Проверяет файл секретов `root:root 0600`, конфигурацию, установленный
  адаптер GetCourse и доступ к таблицам аккаунтов и сессий PostgreSQL.
- Сохраняет закрытую копию `/etc/wep-pril/auth.env` в каталоге
  `/root/wep-pril-auth-public-backups/` с правами `0700`; файл — `0600`.
- Меняет только `AUTH_ENABLED=false` на `AUTH_ENABLED=true`, перезапускает
  `wep-pril-auth`, проверяет анонимную сессию и включает автозапуск systemd.

Ключи, пароли, шаблон, лимит 500 писем в сутки, отписка, схема базы,
материалы, Nginx и права на платные курсы не меняются.
Успех: `AUTH_PUBLIC_ENABLED_OK`, путь `BACKUP_FILE=…` и подтверждение
`BOOT_AUTOSTART_ENABLED; NO_TEMPORARY_IP_GUARD_OR_CLOSE_TIMER`.
Повторный запуск уже включённой службы не переписывает файл и не
перезапускает её; результат — `AUTH_PUBLIC_ALREADY_ENABLED_OK`.

## Ошибка и восстановление

При ошибке активации скрипт восстанавливает прежний файл, перезапускает
закрытую службу и возвращает прежний режим автозапуска. Если настройки
параллельно изменились или откат не прошёл, скрипт не затирает независимые
изменения: останавливает службу и отключает автозапуск. В таком случае
нужна проверка под root перед новым запуском.

В выводе — фиксированные этапы и числовые коды ошибок, без секретов и
вывода команд. Резервную копию не публиковать и не пересылать в чат.
Для срочного закрытия входа достаточно `systemctl stop wep-pril-auth`;
это не изменяет сохранённый флаг и не отменяет автозапуск. Для полного
возврата к закрытому режиму следует восстановить проверенную копию
файла секретов с правами `0600`, вернуть прежний режим автозапуска и
подтвердить ответ `503 auth_unavailable`.

## Проверка после включения

1. Обычный GET `https://app.legkie-rody.ru/api/auth/session` без cookie
   возвращает `200`, `authenticated=false`, `user=null`. Параметры запроса
   к этому адресу не добавляются.
2. На [странице входа](https://app.legkie-rody.ru/login.html) проверяются
   новый код, настоящая сессия, сохранение после обновления страницы и
   выход из профиля. Повторный вход не создаёт дубль GetCourse.
3. API материалов остаётся доступным. Успех публикации GitHub Pages
   не заменяет эту проверку действующего сервера.

Первый сценарий уже пройден в [ограниченном тесте](AUTH_BROWSER_CHECK.md).
Постоянная активация не доказывает нагрузку 1000 активных пользователей,
работу реальных iOS/Android/PWA, восстановление из резервных копий или
готовность остальных функций приложения.

## Локальная проверка

`python -m unittest discover -s deploy -p test_enable_auth_public.py -v`:
11 проверок. Включение, повтор, откат при ошибке запуска/ответа/автозапуска,
сохранение прежнего автозапуска, отказ при остатках теста, защита от
перезаписи параллельных изменений и точечное изменение флага. Настоящие
письма, системные службы и пользовательская база этим не затрагиваются.
