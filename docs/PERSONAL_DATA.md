# Личные записи аккаунта

Решение согласовано 27 октября 2026: личные записи, прочтение статей и избранное сохраняются в существующей PostgreSQL. Давление и самочувствие сохраняются историей; существующие карточки показывают последнее состояние. Первый этап не подключает AI, сообщество, уведомления, оплату и новые поля профиля.

## Хранение и доступ

Таблица `auth_personal_records` связана с `auth_users` через внешний ключ. Типы записей: вес, давление, самочувствие, данные малыша по неделе, шевеления, прочитанная статья и избранное видео. Значения личных показателей не попадают в Git или логи приложения.

`GET /api/auth/personal` возвращает сведения только владельца действующей сессии и `accountId`. `POST` этого маршрута требует тот же аккаунт в заголовке `X-Webpril-Account`, JSON и исходный домен. Сервер получает владельца из сессии под блокировкой строки, а заголовок использует только для проверки: старая форма аккаунта A с новой cookie аккаунта B не запишется в B. Чужой `userId` не принимается. Ответы имеют `Cache-Control: no-store`.

Операции: `addWeight`, `addPressure`, `addWellbeing`, `addMovement`, `setBaby`, `setArticleRead`, `setFavorite`, `import`. Добавления используют UUID: повтор с теми же данными не создаёт второй записи, с другими данными отклоняется. Переключатели прочтения и избранного можно включать и выключать. Чтение возвращает все записи без скрытого ограничения истории. Импорт ограничен 1 000 000 байт, 5000 взвешиваний, 10000 шевелений, 5000 отметок каждого типа и 42 неделями; превышение выдаёт ошибку, а не обрезает данные. Остальные маршруты входа сохраняют прежний лимит тела 4 КБ.

Новые записи давления и самочувствия имеют время; для прежнего значения без даты импорт сохраняет `recordedAt: null`. Время переноса в техническом `created_at` не выдаётся за время измерения. История сортируется по времени измерения, записи без даты идут перед датированными. Старые значения, уже перезаписанные в браузере, восстановить нельзя.

## Интерфейс и перенос

`Фронт/personal-data-api.js` загружает записи и подтверждает сохранение сервером. Вес, давление, самочувствие, данные малыша и шевеления больше не читают бизнес-данные из localStorage. При сетевой ошибке форма сохраняет введённые значения и показывает ошибку; кнопка сохранения не обещает успех. Подтверждённые изменения обновляют остальные открытые вкладки через BroadcastChannel без хранения личных данных в канале.

Отметки прочтения загружаются до сортировки подборок; непрочитанные идут впереди. Сердечко в видеоплеере сохраняет отметку в аккаунте; кнопка избранного в разделе «Мама» открывает список этих видео. Это не добавляет прогресс прохождения купленных курсов и не заменяет демонстрационные видео учебными.

Старые ключи браузера читает только помощник импорта. Он показывает число найденных записей и требует нажать «Да, все записи мои»; до этого сведения не отображаются как личные данные вошедшего аккаунта. «Пока не переносить» сохраняет только временный флаг в sessionStorage этой вкладки. Перенос повторяемый и транзакционный. Имеющаяся серверная запись малыша за ту же неделю сохраняется при конфликте со старой. Исходный локальный ключ удаляется только после подтверждённого ответа и если его содержимое не изменилось во время переноса. Ошибка и смена аккаунта оставляют исходные ключи.

Отзыв сессии закрывает доступ, очищает личное состояние в памяти и закрывает сохранённые панели. Проверки входа каждые 30 секунд и при возврате сохраняются. Браузерная память, cookie входа и обычный кэш ресурсов необходимы для работы интерфейса и не являются самостоятельным постоянным хранилищем личных записей.

## Проверки и выпуск

- Серверные тесты: 92/92 на отдельной PostgreSQL Timeweb с временными схемами. После завершающих исправлений импорта целевой тест повторён локально и на PostgreSQL: 2/2.
- Проверки интерфейсной логики и соседних сценариев: 31/31. Копирование и пробное восстановление: 6/6 автоматических проверок ошибок.
- В браузере на 390 px с подменённым тестовым API проверены сохранение и перезагрузка веса, давление, самочувствие, отказ сети и повтор, данные малыша и шевеления. Это проверка интерфейса, не доказательство опубликованной записи в PostgreSQL.
- При дополнительном прогоне обнаружен старый сбой `tools/test-profile-dates.mjs` о разрешённых ссылках возврата: он ожидает запрет `video.html?id=other`, тогда как действующий `auth-return.js` разрешает внутреннюю страницу. Эти файлы этим этапом не менялись; актуальные `test-auth-return.mjs` проходят. Исправление старого теста не включено в выпуск.

Публикация: `deploy/publish-personal-data.py` принимает архив с закреплённой Git-ревизией, новыми и ожидаемыми прежними SHA-256. До миграции создаёт копию и проверяет восстановление по [инструкции](PERSONAL_DATA_BACKUP.md). Новая таблица добавляется транзакционно, прежние аккаунты и покупки не меняются. Код откатывается к сохранённым файлам при ошибке; рабочая база из архива автоматически не восстанавливается и новые данные не удаляются.

Выпуск `c2f99a8e618fd1436fa95fa6ecda8bf0d6ca5a77` опубликован 27 октября 2026 на https://app.legkie-rody.ru/. Параллельные изменения плеера из GitHub сохранены; после объединения повторно прошли 21 проверки затронутых сценариев. Файлы на сервере сверены с манифестом по SHA-256.

На опубликованной версии в настоящем браузере с двумя временными вымышленными аккаунтами проверены:

- Сохранение веса, двух измерений давления, самочувствия с комментарием; значения сохраняются после перезагрузки.
- Данные малыша на неделе 27 сохраняются, форма недели 28 не получает эти значения; шевеление остаётся после перезагрузки.
- Отметка статьи и избранное видео записываются на сервере; список избранного открывается из «Мамы».
- Старые записи не импортируются до подтверждения; после подтверждения сохраняются. Повторный импорт не дублирует вес; прежние давление и самочувствие не получают выдуманную дату.
- Второй аккаунт имеет пустые списки; после возврата первый сохраняет все записи. Отдельный HTTP-запрос с cookie B и идентификатором формы A получает 409 `account_changed`, данные B не меняются. Анонимный GET получает 401, ответы не кэшируются.
- На ширинах 390 и 320 px формы работают и горизонтального переполнения нет; итоговая консоль проверенного экрана без ошибок. Скриншоты лежат локально в `output/playwright/personal-mom-live.png` и `personal-mom-live-320.png`.

Перед миграцией создан набор `/opt/wep_pril/backups/20261027T141350Z`, восстановление восьми прежних таблиц проверено в отдельной временной базе. После выпуска и удаления тестовых аккаунтов создан набор `20261027T142015Z`; успешно восстановлены все девять таблиц, включая новую таблицу личных записей. Временные аккаунты, их записи, локальные файлы с тестовыми cookie и временные базы восстановления удалены. Таймер ежедневной копии активен. Полный проход всех платных курсов, реальный вход по письму и нагрузка в этом выпуске не проверялись.
