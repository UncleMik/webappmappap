# Проверка голосования — 2026-11-13

## Причина и исправление

POST `/api/auth/weekly-poll` сохранял голос и возвращал `choice` и `counts`,
но не `accountId`. Интерфейс проверяет принадлежность каждого ответа аккаунту;
поэтому успешную запись он ошибочно отклонял с сообщением «Аккаунт изменился.»
и не открывал обсуждение.

Исправление `97c0894`: ответ `vote()` теперь также содержит `accountId`, взятый
из проверенной сервером сессии. Правила доступа и начислений не менялись.

## Проверено

- Локально на PGlite: `node --test backend/test/stars-core.test.mjs` — 22/22;
  `node --test backend/test/admin.test.mjs backend/test/club-chat.test.mjs` — 47/47.
  Добавлены проверки идентификатора в ответе, неизменности первого выбора,
  единственной записи голоса и чтения сохранённого ответа новым аккаунтом вне пилота.
- Браузер с фикстурами, 390 px: исходный ответ воспроизводит ошибку интерфейса;
  исправленный ответ открывает обсуждение.
- На настоящем HTTPS создан отдельный временный синтетический аккаунт вне
  пилота, без отправки писем и создания внешней карточки GetCourse.
  До исправления подтверждены HTTP 200 и отсутствие `accountId`, при этом
  голос уже присутствовал в PostgreSQL.
- После публикации реальное нажатие в форме открыло обсуждение текущего
  опроса. При возврате и перезагрузке выбранный ответ отмечен, форма скрыта,
  ссылка обсуждения доступна. Переполнения по ширине нет на 320/390/500 px.
- Повторный настоящий HTTPS POST с другим вариантом вернул исходный выбор
  и верный `accountId`; свежий GET сохранил выбор, PostgreSQL содержит один голос.
- Временный аккаунт, его голос и сессия удалены. Старый тестовый cookie
  больше не подтверждает вход; локальные и серверные файлы полномочий удалены.
