# Обязательный вход — 19 октября 2026

Пользователь поручил закрыть все разделы без аккаунта и действующего входа,
включая кнопку «В приложение» и прямые ссылки. Открыты только форма входа
и необходимые ей файлы. Само наличие cookie не является подтверждением:
проверяется действующая серверная сессия.

## Реализация

- Nginx проверяет сессию через внутренний `auth_request` перед выдачей
  страниц, API материалов, изображений и остальных ресурсов приложения.
  `/api/auth/check` возвращает 204 для сессии, 401 без неё, 503 при ошибке.
- Страницы без входа перенаправляются на форму; запросы к материалам получают
  401. Ошибка службы входа также закрывает доступ. Ответы с материалами имеют
  `private, no-store`; Nginx не передаёт условный ETag-запрос к API статей.
- Клиентский gate скрывает страницу до проверки и повторяет проверку при
  возврате из истории, фокусе и возврате во вкладку. На выходе сбрасывается
  всё окно с сохранёнными панелями разделов.
- После входа разрешён возврат только на существующие внутренние разделы;
  параметры недели, материала и видео сохраняются. Внешние адреса и служебные
  страницы входа/онбординга не могут стать адресом возврата.
- GitHub Pages публикует только перенаправления на основной сайт. HTML,
  JavaScript и изображения материалов в новом артефакте отсутствуют.
  Старые ссылки по IP перенаправляются на основной домен.
- Ранее согласованная общедоступность трёх исходных MP4 вне приложения
  сохраняется. Эта правка не меняет размещение исходников в GetCourse.

## Выпуск на Timeweb

`deploy/publish-required-login.py <полный SHA коммита>` запускается под root.
Скрипт скачивает четыре закреплённых файла и сверяет SHA-256. Добавляет
проверки к существующему HTML/службе входа, сохраняя прочие изменения,
включая онбординг и профиль. Неизвестную конфигурацию Nginx не заменяет.
Секреты, схема и данные обеих баз не меняются.

Перед заменой создаётся закрытая копия файлов с manifest в `/root/`.
Проверяется `nginx -t`, перезапускается только служба входа, выполняется
reload Nginx. Скрипт сам проверяет анонимные запросы к страницам, API,
изображениям и старому IP. Ошибка запускает откат. Во время перезапуска
входа запросы к защищённым разделам могут ненадолго получить ошибку.

Ожидаемый результат: `REQUIRED_LOGIN_PUBLISHED_OK`. После этого нужно
независимо проверить основной сайт и настоящий вход в браузере.

## Проверено и ограничения

- До исправления тест нового проверочного маршрута воспроизвёл отсутствие
  защиты (405 вместо 401). После интеграции свежего онбординга: 24 теста бэкенда, 2 теста
  безопасного возврата и 6 проверок выпуска/отката прошли.
- В Chrome на изолированном стенде с настоящей службой входа и тестовой
  PostgreSQL WASM проверены email/код, возврат к неделе 27, обновление,
  выход, кнопка «Назад», прямые ссылки на все 15 страниц, «В приложение»
  и недоступность проверки сессии. Письма и GetCourse заменены тестовыми
  адаптерами; действий в школе и настоящих писем эти проверки не создают.
- На 390×844 вход и открытый после входа раздел без переполнения.
- Официальный Nginx 1.28.0 с `http_auth_request_module` принял конфигурацию
  (`nginx -t`). Запуск локального Nginx отклонён автоматической проверкой
  с причиной `blocked by policy`; его HTTP-ответы локально не проверены.
- Публикация и проверки серверного ограничения на Timeweb ещё ожидаются:
  SSH отклоняет доступ агента, нужна команда в консоли пользователя.
  Браузерные проверки клиента не доказывают установленную серверную защиту.
