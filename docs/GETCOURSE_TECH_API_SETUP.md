## Права школьного ключа

Отдельный школьный ключ с правом **«Только для чтения»** достаточен по назначению
для чтения покупок и тренингов: [описание прав](https://getcourse.ru/blog/1053682)
запрещает такому ключу создание и изменение данных. Фактический набор прав
полученного ключа отдельно не проверен. При этом четыре нужных GET-метода
[схемы Tech API](https://getcourse.ru/pl/postback/redoc/schema) уже успешно
ответили в аккаунте школы; это подтверждает их работоспособность с полученной
парой ключей, но не доказывает, что ключ имеет именно режим «Только для чтения».

Токен Tech API составляется как `<ключ разработчика>_<ключ школы>` и передаётся
через Bearer только сервером. В браузер приложения, Git, логи и переписку
секреты не включаются. `GETCOURSE_IMPORT_KEY` обслуживает отдельную регистрацию
через legacy API; ключи Tech API его не заменяют.

## Проверенные чтения, 23 октября

Итоговый серверный клиент прошёл 7 локальных тестов и реальные запросы всех
четырёх методов. `GET /pl/api/v1/common/get-trainings` вернул HTTP 200,
`status: true` и 2475 тренингов; все 11 проверенных ожидаемых ID найдены.
`GET /user/get-fields` для контрольной бесплатной карточки подтвердил
совпадение ID и email. Для неё `GET /user/get-purchases` вернул 0 покупок,
а `GET /user/get-trainings` — 80 записей. Другая прежняя контрольная карточка
также дала 0 покупок. Список доступных тренингов сам по себе не является
подтверждением оплаченных прав.

На одной старой оплаченной покупке предложения Экспресс ответ API совпал с
интерфейсом по покупке, продукту, пользователю, началу, окончанию и типу
периода. При этом в интерфейсе заказ завершён и оплачен, покупка не отключена,
а API вернул `is_actual=1`, `is_payed=0`, `state=null`. Значит, проверка прав не
может просто требовать `is_payed=1`. Это одно наблюдение, а не установленная
семантика всех состояний. Отказы, отмены, неоплата, отключение покупки и
условия вложенных тренингов ещё не проверены.

Клиент подключён к серверной [проверке на пять минут](COURSE_ACCESS_CHECKS.md)
и хранению одного последнего результата в PostgreSQL. Согласовано: после
истечения срока при неудаче обновления платный материал не выдаётся.
GET `/api/auth/course-check` сообщает только свежесть результата для текущей
сессии. Он не возвращает покупки или платные материалы. Семантика состояний
и дочерних условий, дополнительная событийная синхронизация и защищённый
показ платного видео остаются открытыми.

## История подготовки, 22 октября

22 октября школьный кабинет поддерживал создание ключа чтения, но отдельные
ключи ещё не были получены. В открытом тогда личном профиле Микаила на
`getcourse.ru` заявка разработчика была недоступна. Поэтому ключ согласовали
оформить через профиль ответственного техспециалиста школы; это препятствие
позднее перестало быть блокером для чтений. Профиль фактической выдачи
полученного ключа не проверялся; работающая регистрация не менялась.

Цель интеграции: сервер Node.js приложения проверяет фактический доступ
ученицы к конкретным продуктам школы, включая старые покупки тех же продуктов.
Чтение не меняет покупки, оплаты и заказы и само по себе не решает выдачу видео.
