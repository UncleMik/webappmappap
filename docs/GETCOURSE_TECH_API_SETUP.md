# Ключи Tech API GetCourse — 22 октября 2026

Для приложения нужны два разных ключа:

| Ключ | Где оформляется | Текущее состояние |
| --- | --- | --- |
| API-ключ школы, только чтение | [Лёгкие роды → АПИ](https://legkierody.ru/pl/saas/account/api) | Кабинет школы проверен; форма создания доступна, право «Только для чтения» есть. Новые ключи агент не создавал. По договорённости ключ создаёт техспециалист и передаёт защищённо. |
| Ключ разработчика | [Заявка GetCourse](https://getcourse.ru/issuedeveloperkey) | Оформляется на согласованный профиль ответственного техспециалиста школы на getcourse.ru. В открытом центральном профиле Микаила заявка недоступна; не подана. |

`legkierody.ru` — правильный кабинет школы `schoolrodi.getcourse.ru`. Он не заменяет центральный профиль `getcourse.ru` для заявки разработчика. На странице заявки сейчас перечислены требования: регистрация больше месяца назад, подтверждённые email и телефон, имя и фамилия, привязанный Telegram-бот GetCourse. Открытая форма явно сообщает «Вы не можете подать заявку». По этому общему сообщению нельзя установить все конкретные невыполненные условия. Профили, контакты и настройки безопасности агент не менял.

## Права школьного ключа

Нужен отдельный ключ «ВебПрил — чтение доступов Tech API» с правом **«Только для чтения»**. [Официальное описание прав](https://getcourse.ru/blog/1053682) запрещает такому ключу создавать или изменять данные. Нужные методы [схемы Tech API v2](https://getcourse.ru/pl/postback/redoc/schema) — `GET /user/get-purchases`, `GET /user/get-trainings`, `GET /common/get-trainings`. По смыслу прав чтения достаточно; схема не описывает отдельные разрешения каждого метода. Окончательное подтверждение — успешные запросы на legkierody.ru с обоими ключами. Сейчас такой проверки нет.

Токен Tech API составляется как `<ключ разработчика>_<ключ школы>` и передаётся через Bearer на сервере. В браузер приложения, Git, логи и переписку секреты не включаются. Действующий `GETCOURSE_IMPORT_KEY` обслуживает отдельную регистрацию через legacy API и требует записи; новым ключом чтения его не заменять. Ключи других интеграций сохраняются.

## Что нужно для продолжения

1. Ответственному техспециалисту войти именно в свой профиль **getcourse.ru**, выполнить требования страницы и открыть заявку. Доступ к legkierody.ru сам по себе этого не делает.
2. Подать заявку разработчика от этого профиля. Если нужный профиль будет открыт в Chrome, агент сможет продолжить подготовку формы; создание ключа и принятие юридических условий потребуют соответствующего подтверждения на шаге действия.
3. Техспециалисту создать школьный ключ чтения и передать оба секрета защищённым способом для закрытого хранения на текущем сервере. После этого выполнить ограниченные запросы чтения и проверить реальные периоды доступа; частота синхронизации и поведение при сбое остаются отдельными решениями.

Описание интеграции для заявки: веб-приложение школы «Лёгкие роды» на `app.legkie-rody.ru` проверяет действующий доступ ученицы к конкретным купленным продуктам аккаунта `legkierody.ru`, включая прежние покупки тех же продуктов. Запросы выполняет сервер Node.js. Изменение покупок, оплат и заказов в эту интеграцию не входит. Способ защищённого показа платных видео через GetCourse пока не подтверждён; ключ разработчика не считается его решением.

## Краткий ответ техспециалисту

Для чтения покупок и доступных тренингов нужен отдельный школьный API-ключ с правом «Только для чтения». После получения обоих ключей проверим доступ запросами именно в аккаунте «Лёгкие роды». Работающую регистрацию оставляем на её отдельном ключе записи.

Ключ разработчика оформляем на ваш профиль getcourse.ru. Из открытого школьного кабинета эту заявку подать нельзя, а в доступном нам центральном профиле GetCourse пока блокирует подачу. Просим открыть подходящий профиль либо подать заявку через getcourse.ru/issuedeveloperkey. Описание интеграции подготовлено выше. Секреты передавайте защищённым способом.
