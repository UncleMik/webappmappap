# Предложения GetCourse для приложения

22 октября 2026 года в авторизованном интерфейсе GetCourse проверены три предложения, переданные пользователем. Точный снимок их названий, цен, продуктов, ID тренингов и сроков настроек: [getcourse-offers-2026-10-22.json](content/getcourse-offers-2026-10-22.json). Это **инвентаризация настроек** (`inventory_only`), а не работающий механизм оплаты или выдачи доступа.

| Предложение | Настройка цены | Состав в предложении |
| --- | ---: | --- |
| [Экспресс](https://legkierody.ru/pl/sales/offer/update?id=8835218) | 2 800 ₽ | 6 тренингов, каждый на 183 дня |
| [Все включено](https://legkierody.ru/pl/sales/offer/update?id=8835266) | 4 680 ₽ | 5 тренингов на 365 дней и участие в онлайн-встречах на 60 дней |
| [ПРОФИ](https://legkierody.ru/pl/sales/offer/update?id=8835331) | 7 490 ₽ | 22 тренинга на 1095 дней, онлайн-встречи и Telegram-чат на 60 дней каждый |

Названия продуктов и ссылки на их настройки перечислены в JSON-снимке. Два продукта, связанные с онлайн-встречами и Telegram-чатом, имеют `trainingId: null` и отдельные ID групп: 2699461 («Участники онлайн-встреч - Все включено, Все включено ПРО, МОРИМ, VIP») и 3580357 («Доступ к чату ЛР_все включено_ПРО») соответственно. В настройках ПРОФИ отмечено открытие всех частей после оплаты, частичная оплата доступа не открывает; для остальных предложений соответствующее поле в снимке не зафиксировано. Цены — состояние предложений на дату снимка, а не утверждённые правила покупки или интеграция оплаты в приложении.

Пользователь подтвердил, что действующим ученицам со старыми покупками **тех же продуктов** надо учитывать имеющийся доступ. При проверке прав нужно устанавливать доступ к каждому конкретному продукту и его фактические даты по GetCourse. Совпадение одного продукта не даёт весь тариф; сроки из новых предложений не продлевают старую покупку.

Согласовано: серверный модуль курсов — Node.js, каталог материалов — SQLite, права учениц и результаты проверки GetCourse — PostgreSQL. Платные права проверяются сервером по конкретному продукту и фактическому периоду доступа в GetCourse. Это выбор хранилищ и границы проверки, а не действующий модуль платного доступа.

Сейчас код приложения обращается к GetCourse только при регистрации; платная синхронизация ещё не реализована. В действующей конфигурации Timeweb есть `GETCOURSE_IMPORT_KEY`, ключей Tech API нет. [Официальная схема Tech API](https://getcourse.ru/pl/postback/redoc/schema) описывает авторизацию ключом разработчика и ключом школы, а также чтение покупок и доступных тренингов. Метод выдачи видео через Tech API при проверке не обнаружен. Наличие API-метода в схеме ещё не подтверждает успешную работу с ключами школы и не определяет точную семантику старых покупок, сроков, отмен и дочерних тренингов.

Тексты 749 уроков перенесены в закрытые черновики каталога; подробности ниже. Платный backend доступа не готов, ключ разработчика Tech API ещё не получен. Нужно сопоставить реальные покупки и периоды на обезличенных примерах и проверить правила каждого дочернего тренинга. Правила доступа к чатам приложения и ИИ остаются на согласовании. Частота синхронизации, вебхуки, срок актуальности сохранённых результатов и поведение при сбое GetCourse также открыты.

Выборочная проверка настроек тренингов показала: основной тренинг Экспресс 935397478 и бонус 935397517 имеют `access_type=none` («только те, кто купил тренинг»); модуль 935397576 и папка бонусов 935397494 имеют `access_type=parent`. У всех четырёх `noaccess_mode=not_show`. Эта проверка не охватывает остальные тренинги. Бонус с собственным условием покупки нельзя открыть лишь потому, что доступен родитель; при переносе структуры нельзя рекурсивно раскрывать всю папку без проверки условий каждого дочернего тренинга.

## Подготовка ключей Tech API, 22 октября

Технический специалист школы сообщил: ключ разработчика ещё не оформляли; школа готова создать отдельный ключ и передать защищённым способом. Для запланированных запросов чтения покупок, тренингов и групп рекомендуется минимально необходимый вариант школьного ключа «Только для чтения». [Описание прав GetCourse](https://getcourse.ru/blog/1053682) разрешает чтение и запрещает создание/изменение данных. Схема Tech API не уточняет соответствие этого режима каждому методу; работоспособность подтвердить реальными запросами после получения обоих ключей. Существующий ключ регистрации не заменяется: создание карточек требует записи.

Открыта [официальная страница заявки](https://getcourse.ru/issuedeveloperkey). Для подачи нужны профиль на getcourse.ru старше месяца, заполненные имя/фамилия, подтверждённые email и телефон, привязанный Telegram-контакт/бот GetCourse. Согласовано оформить ключ разработчика через профиль ответственного технического специалиста школы на getcourse.ru, а отдельный ключ школы создать в legkierody.ru. Личный профиль Микаила для заявки не используется, школьный профиль менять не требуется. Заявку пока не отправляли, ключ разработчика не получен; его выдача зависит от GetCourse. Уточнение ключей не означает готовность платного модуля или разрешение ослабить защиту видео.

## Публикация каталога предложений, 22 октября

Каталог размещён на Timeweb: [страница тарифов](https://app.legkie-rody.ru/courses.html). SQLite содержит 3 предложения, 30 продуктов и 36 позиций состава (6/6/24). Новый `GET/HEAD /api/course-offers` возвращает только названия, цены, типы продуктов и длительности. В ответах нет административных ссылок, ID групп/тренингов, адресов видео и сведений учениц. Nginx проверяет вход перед страницей, API, JS и CSS, как для остальных материалов.

Существующий экран показывает Экспресс — 2800 ₽, Все включено — 4680 ₽, ПРОФИ — 7490 ₽. Полный исходный список каждого предложения открывается кнопкой «Состав тарифа». Удалены демонстрационные тарифы, тестовая оплата и вымышленный отзыв. Этот экран описывает предложения; покупки и права конкретной ученицы он не выдаёт. Уроки и защищённый просмотр ещё не подключены.

Проверены повторный импорт, откат при ошибке, сохранность статей/недельного контента, ответы GET/HEAD/ошибок; 6 независимых проверок каталога и прежних API прошли. На изолированном стенде Playwright с моделируемой сессией проверены ширины 320/390/500/1440, загрузка без демо, 503, повтор, точные 36 названий, закрытие диалога и отсутствие переполнения. На рабочем сайте через действующую сессию проверены все три цены и составы 6/6/24; фактическая ширина при проверке Chrome — 520 CSS px. Без сессии API, JS и CSS дают 401; страница направляет ко входу.

Перед установкой создана закрытая копия `/root/wep-pril-course-offers-backup-1792689115344902519`. Для шести файлов выпуска проверены исходные и новые SHA-256; перед импортом сделана резервная копия SQLite. После публикации побайтные отпечатки записей articles и weekly_content не изменились, API статей по-прежнему возвращает 126 статей. Перезапущена только служба контента `wep-pril`; служба входа, PostgreSQL, ключи и конфигурация Nginx не менялись. Локальные материалы QA и выпуска: `output/auth-qa/course-offers-release/`, `output/playwright/course-offers/` (в Git не входят).

## Закрытая структура учебных материалов

После публикации тарифов через авторизованный интерфейс школы собраны два приватных снимка структуры. Экспресс: все 6 исходных продуктовых корней, 49 разделов, 216 уникальных уроков. Полная программа: все 22 исходных корня, 73 раздела, 533 уникальных урока. Очереди обнаруженных вложенных разделов пусты, настройки доступа разделов проверены в интерфейсе. Девять уроков полной программы явно помечены «Не показывается ученикам», статус остальных уроков не подтверждён.

Это инвентаризация дерева материалов, не состав выданных прав по тарифу. Связь с родительским продуктом отражает происхождение, а не разрешение; дополнительные вложенные продукты не добавлены в разрешённый состав. На этом этапе страницы самих уроков, тексты, видео, вложения, покупки и сведения учениц не собирались. Последующий перенос текстов описан ниже. В рабочем приложении уроки по этим снимкам не выдаются.

Файлы `output/auth-qa/course-inventory/express-program.json` и `full-program.json` исключены из Git. На сервер сохранена побайтная копия в `/opt/wep_pril/deploy/course-inventory-20261022/`: каталог 0700, файлы 0600; оба SHA-256 совпали с локальными источниками. Копии находятся вне корня сайта. Проверены уникальность ID, существование родителей и отсутствие адресов видео/ссылок, токенов и email в снимках. Следующий перенос содержимого описан ниже.

## Тексты в закрытых черновиках, 22 октября

По поручению пользователя перенесены тексты всех 216 уроков Экспресс и 533 уроков полной программы: 4666 упорядоченных блоков с точным видимым текстом, безопасным структурным HTML и таблицами. Прочитаны раскрываемые конспекты, отдельно обработаны старые шаблоны и аудиоплейлисты. Видимые авторские адреса и контакты сохранены как часть текста; href/src, iframe URL, комментарии, ответы учениц, формы и браузерные данные исключены. Динамические ID builder-item заменены порядком внутри стабильного исходного блока без изменения учебного текста. Исходные captures до нормализации также сохранены приватно.

Изображения, PDF и аудио представлены описаниями вложений; сами файлы пока не перенесены. Видеоблоки содержат тип источника и доступный безопасный ID; у части источников ID или соответствие файлу требуют проверки. Количество уроков и видеоблоков не означает количество уникальных видеозаписей. Видеофайлы остаются в GetCourse; защищённый платный просмотр в приложении пока не подключён.

На Timeweb в существующую SQLite импортированы `course_program_drafts` и `course_lesson_drafts`. Все 749 записей имеют закреплённый CHECK статус `delivery_status='unavailable'`; HTTP-маршрутов выдачи черновиков нет. Исходный статус хранится отдельно и не становится разрешением. Права, покупки, PostgreSQL, ключи и Nginx не менялись, службы не перезапускались. Приватные источники: `/opt/wep_pril/deploy/course-content-20261022-6e83f9b8/` (0700/0600, вне webroot); резервная SQLite: `/root/course-content-20261022-6e83f9b8/articles-before.sqlite`. В Git входят только код, синтетические тесты и документация; локальные материалы — `output/auth-qa/course-content/`.

Прошли 7 тестов импорта и прежнего каталога, полный локальный импорт и независимые контрпримеры с усечённым реестром и посторонними полями. Выборочные живые сверки по обеим программам совпали; два текстовых блока с раскрываемым конспектом дополнительно совпали побуквенно с source innerText. На сервере все 749 сохранённых JSON сверены с подготовленными исходниками, SHA-256 совпали. Отпечатки прежних статей (126), недельных записей (129), продуктов (30), предложений (3) и их позиций (36) до/после одинаковы. Рабочая страница тарифов загружается, запрос приватного снимка через сайт даже с действующей сессией даёт 404. Платный доступ и воспроизведение этой проверкой не подтверждены.
