# Рабочий онбординг

Согласовано 19 октября 2026 года: пользователь подтвердил обязательность
срока или даты рождения малыша и хотя бы одной цели и поручил реализацию.

## Сценарий

1. Единый вход/регистрация: email → настоящий код. GetCourse связывается
   до выдачи сессии по прежнему правилу; пароль не добавляется.
2. Выбор «Я беременна» или «Я уже мама».
3. Имя и данные этапа. Для беременности: один способ — дата зачатия,
   ПДР либо недели и дни. Для мамы — дата рождения малыша.
4. Хотя бы одна цель из семи вариантов своей ветки. В интерфейсе знакомство
   остаётся тремя шагами: этап, данные, цели. Пропуска нет.
5. Сервер сохраняет профиль, затем открывается приложение или выбранное
   ранее бесплатное видео. Заполненный аккаунт при следующем входе
   сразу открывает приложение; незаполненный возвращается к знакомству.

Промежуточные ответы живут только в памяти открытой анкеты: при возврате
к предыдущему шагу сохраняются, после обновления незавершённая анкета
начинается с выбора этапа. Завершённый профиль хранится в PostgreSQL
и доступен из новых сессий и устройств. Демо localStorage не импортируется.

## Хранение и персонализация

`auth_users.profile` — nullable JSONB в существующей отдельной PostgreSQL.
Канонические поля: имя, этап, способ расчёта, ПДР либо дата рождения малыша,
индексы целей и серверная дата завершения. В GetCourse и письма профиль
не передаётся. Сервер берёт ID из действующей сессии, проверяет источник
запроса, имя, реальные календарные даты, срок и обязательные цели.

Расчёты используют календарный день Москвы и арифметику целых дней.
«Сегодня», «Мой путь», календарь, карточки «Мама» и «Малыш» используют
неделю профиля. Явно выбранная неделя в URL сохраняет приоритет.
Переход к материнству по наступлению ПДР не выполняется.

Для мамы отображается возраст ребёнка; персональные карточки беременности
и рекомендации 27-й недели скрыты. Библиотека недель беременности остаётся
доступной как библиотека. Новые послеродовые подборки не выдумываются.
Имя, срок/возраст и цели видны в профиле/личных данных.
Редактирование завершённой анкеты, перенос прежних личных записей из
браузера, синхронизация покупок и подбор рекомендаций по целям — отдельные этапы.

Бесплатные три видео требуют действующей сессии и завершения обязательного
онбординга; покупки для них не требуются. Сервер возвращает `401` без
сессии и `403 onboarding_required` без профиля. Плеер предлагает заполнить
данные и сохраняет возврат к выбранному видео.

## Проверки и публикация

- 31 проверка входа, профиля, видео, интерфейса аккаунта и согласованности дат.
- Издатель: 6 локальных проверок; 2 POSIX-проверки пропущены на Windows.
- В изолированном браузерном стенде: обе ветки, все три способа расчёта,
  обязательность данных, возврат, ошибка сохранения и повтор, новый вход,
  обновление, новая вкладка, iframe-навигация, выход и возврат к видео.
- Настоящие материалы школы прочитаны через API: личная 18-я неделя в
  карточках, статьях, календаре и «Моём пути»; выбор 26-й недели сохранён.
- Размеры 320 и 390 px без горизонтального переполнения, на ПК колонка 500 px.

Выпуск `a79b5ee` опубликован на Timeweb: `ONBOARDING_PUBLISHED_OK`.
Все 25 изменённых файлов интерфейса сверены по SHA-256 с выпуском.
На отдельной PostgreSQL сервера — 20/20 проверок входа, профиля и видео,
ошибок и пропусков нет. Служба работает, анонимная сессия — `200`,
запись профиля без входа — `401`, материалы — `200`, доступно 126 статей.
GitHub Pages Actions `39303399082` завершился успешно. После отдельного
решения об обязательном входе GitHub Pages публикует только переход
на рабочий вход школы; наличие такого перехода проверено по HTTPS.

В Chrome на рабочем HTTPS действующая настоящая сессия открыла
обязательный первый шаг. Просмотрены обе ветки следующего шага:
имя и способы расчёта, имя и дата рождения малыша; без данных кнопка
продолжения недоступна. После обновления снова первый шаг.
За пользовательницу личные данные не вводились и профиль не сохранялся;
письмо с кодом повторно не отправлялось, поскольку сессия уже действовала.
Полное сохранение обеих анкет проверено на изолированном браузерном стенде
и через HTTP на отдельной PostgreSQL, а не в личном рабочем аккаунте.

На действующем сервере HTML плеера обновлён точечным вариантом
`deploy/onboarding-video-live.html`: меняется только версия загрузчика.
Независимые изменения полноэкранного плеера из других выпусков этим
издателем не переносятся; канонический `Фронт/video.html` сохраняет их в Git.
Издатель `deploy/publish-onboarding.py` сверяет закреплённые SHA-256,
создаёт закрытую копию базы и старых файлов, добавляет nullable колонку,
меняет только перечисленные файлы и перезапускает службу входа.
При ошибке возвращает старые файлы; добавленная пустая колонка не удаляется.
Рабочая база не восстанавливается поверх новых действий пользователей.
Полное восстановление базы и нагрузка 1000 активных пользователей не проверялись.
