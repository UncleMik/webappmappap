# Отдельные беседы с Ларой

Согласовано 6 ноября 2026 года: пользователь одобрил четыре состояния
прототипа и поручил реализовать их на сайте. Прототип: текущая беседа с
кнопкой из трёх полосок вместо «История», боковое меню «Чаты с Ларой»,
«Новый чат», список бесед и переключение между ними.

## Поведение

- Список группируется по московским датам: «Сегодня», «Вчера», «Ранее».
  Текущая беседа выделена; её заголовок виден над перепиской.
- Новый чат начинается пустым. Его создание не вызывает модель и не
  расходует дневной лимит. Название берётся из первого вопроса, без
  дополнительного обращения к модели. Поиск, переименование и удаление
  бесед в эту задачу не входят.
- Прежняя общая веб-переписка сохраняется одной беседой «Предыдущая
  переписка». Сообщения не распределяются по темам автоматически.
- История хранится в существующей PostgreSQL на Timeweb и доступна
  после нового входа. Данные одной беседы не подмешиваются в другую
  ни в интерфейсе, ни в контексте модели.
- Ответ на ожидающий вопрос остаётся в исходной беседе, даже если
  ученица переключилась. Черновики и вложения не переносятся в другой
  чат; запись голоса при переключении останавливается.
- Хранение сообщений остаётся 90 дней. Лимит общий на аккаунт:
  5 вопросов для бесплатного доступа, 30 при действующей покупке,
  обновление в 00:00 Москвы. Создание новых бесед лимит не сбрасывает.
- Распознавание и генерация остаются на немецком сервере; правила
  Лары, доступ к материалам, вложения и голосовой ввод сохраняются.

## Сервер

Новая таблица бесед и принадлежность запросов добавляются отдельной
миграцией. Перед её применением создаётся резервная копия PostgreSQL
и проверяется восстановление в отдельную временную базу. Миграция
сохраняет существующие запросы, их UUID, ответы, статусы и суточный расход.

Все операции проверяют вход, аккаунт и принадлежность беседы на сервере.
Один UUID запроса не может использоваться в другой беседе. Продолжение
истории модели выбирается только из выбранной беседы и по прежним
правилам доступа. Старая версия интерфейса обращается только к своей
прежней общей беседе, без объединения всех новых чатов.

`GET /api/auth/ai/conversations` читает первую страницу списка,
`POST /api/auth/ai/conversations/read` — продолжение,
`POST /api/auth/ai/conversations` создаёт беседу по UUID клиента с
безопасным повтором. История, отправка и проверка результата передают
`conversationId`. Размер страниц — 30, курсоры формирует сервер.

## Проверка выпуска

До публикации проверяются изоляция аккаунтов и бесед, сохранение прежней
истории, общий лимит, повтор UUID, контекст модели, ожидающие ответы,
ошибки сети, файлы, голос, выход из аккаунта и мобильное меню. После
публикации проверяются установленные файлы и синтетические сценарии;
результаты фиксируются отдельно с различием между подменёнными внешними
сервисами и настоящим обращением к модели.
