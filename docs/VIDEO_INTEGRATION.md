# Три видео в «Моём пути»: источники и способ подключения

Реализовано, опубликовано и проверено на рабочем домене 19 октября 2026 года.

## Согласованный объём

Пользователь подтвердил три темы: дыхание в схватках, позы и самомассаж,
дыхание и позы в потугах. Разместить в «Моём пути» вместо демонстрационных
видео, бесплатно после входа. Сначала проверить возможность подключения
через API GetCourse. После исследования пользователь отдельно разрешил
прямые ссылки и отсутствие защиты от скачивания для этих трёх записей.

## Найденные исходные ответы поддержки

В чате «Собрать вопросы для архитектуры веба»
(`01a114f1-ab2d-7020-9814-9713f593ca66`) найдены исходные ответы,
переданные пользователем 7, 8 и 10 октября. Ответы 7–8 октября сохранены
также во вложениях этого чата «Вставленный текст.txt». Полные подписанные
ссылки из примеров сюда не перенесены.

- **7 октября:** поддержка разрешает использовать прямую ссылку на файл
  из хранилища. Она общая для всех учениц. Для просмотра без дополнительного
  входа в GetCourse нужные файлы должны быть общедоступными. Стандартный
  плеер и его водяные знаки при таком подключении не используются.
- **8 октября:** поддержка приводит пример временного адреса после
  перенаправления с исходной ссылки. Это выдача файла, а не отдельный
  документированный API видеопросмотра. Поддержка не рекомендует такой
  способ: файловое хранилище предназначено для скачивания исходников,
  не даёт возможностей адаптивного видеохостинга и защиты его плеера.
  Скрытая в коде ссылка остаётся доступной браузеру; скрытие не защищает её.
- **8 октября:** плеер можно разместить через виджет GetCourse. Для проверки
  сегмента требуется авторизация в GetCourse; поддержка рекомендует общий
  основной домен для страницы приложения и виджета.
- **10 октября:** готового сквозного входа и одноразовой ссылки авторизации
  через API нет. Сегмент скрывает блок при загрузке страницы, но не прекращает
  уже начатый просмотр после отзыва доступа. Работа авторизации виджета
  зависит от браузерной политики cookies.

Приложение размещено на `app.legkie-rody.ru`, школа — на `legkierody.ru`:
это разные основные домены, несмотря на сходство названий. Существующий
вход приложения сам по себе не создаёт браузерную сессию GetCourse.

## Реализация и публикация

Пользователь разрешил прямые ссылки после объяснения возможности скачивания
и передачи исходника. В GetCourse у файлов 292597505, 155519950, 155516409
установлено «для всех» вместо «по умолчанию». Другие файлы не менялись.
Постоянные адреса записаны в `backend/auth/weekly-videos.mjs`; временные
CDN-подписи и данные административной сессии в приложение не переносятся.

`GET /api/auth/videos/:id` использует существующую серверную сессию,
возвращает 401 без неё и выдаёт адрес только одного из трёх согласованных
файлов после входа. Ответ не кэшируется, покупка не требуется.
Общедоступный исходник не защищён этим маршрутом после выдачи адреса.

`weekly-videos.js` задаёт единый каталог карточек и плеера. HTML video
запрашивает запись после нажатия; соседняя запись и возврат сохраняют
неделю. После окончания открывается следующая запись без автозапуска;
последняя показывает завершение. Остальные демонстрационные сценарии
плеера вне «Моего пути» сохраняются. Вход возвращает к выбранному видео.
На GitHub Pages кнопка входа ведёт на рабочий домен приложения.

Локально прошли 17 проверок входа и выдачи видео, а также четыре проверки
публикации: штатное обновление и повтор, отказ при чужой версии файла,
отказ при неверном хеше загрузки, откат при неуспешной проверке службы.
В Chrome проверены начало воспроизведения всех трёх MP4, пауза,
перемотка, переход без автозапуска, завершение последней записи, вход
с возвратом и ширины 320/390 px. В отдельном встроенном браузере без
сессии GetCourse первое видео воспроизводится после входа только
в приложение на том же тестовом стенде.
Размеры исходников: около 154 МБ, 259 МБ и 1,3 ГБ. Адаптивного качества
в этом временном варианте нет; плавность на медленном интернете не проверена.

Скрипт `deploy/publish-weekly-videos.py` обновляет только выбранные файлы
с проверкой исходных и новых хешей, сохраняет копию и перезапускает
уже работающую службу входа. Nginx, секреты, базы и подписки не меняет.
Известное ограничение доступа к консоли Timeweb требует ручного применения
готовой команды пользователем; это не повторное согласование публикации.

## Проверка рабочего сайта после установки

Пользователь выполнил подготовленную команду и сообщил
`WEEKLY_VIDEOS_PUBLISHED_OK`. Независимая проверка HTTPS подтвердила:

- Все восемь обновлённых файлов интерфейса на `app.legkie-rody.ru`
  побайтно совпадают с проверенным релизом 364dcfda90b9ed12177cd138753dfde26e060248
  после нормализации окончаний строк. GitHub Pages также обновлён и проверен.
- Без cookie `/api/auth/session` отвечает 200 с `authenticated=false`,
  маршрут видео — 401 `sign_in_required`. В отдельном браузере без входа
  воспроизведение недоступно и показана кнопка входа с возвратом к видео.
- В текущей действующей сессии приложения запущены все три MP4:
  время воспроизведения увеличивается, `readyState=4`, ошибок video нет.
  Фактические длительности исходников — 703,269 / 201,375 / 601,378 секунды.
  После загрузки плеер уточняет длительность по самому файлу.
- Работают пауза и переход между записями. Следующая запись открывается
  без источника и без автозапуска. После обновления страницы вход сохраняется,
  повторный просмотр можно начать вручную. Возврат сохраняет неделю 27.
- На фактической ширине 390 CSS px документ также имеет ширину 390 px.
  Проверены плеер и карточки после возврата. Масштаб Chrome не менялся,
  временный размер проверки сброшен.
- API материалов отвечает 200, 126 статей. Секреты, базы данных, покупки,
  группы и рассылки этим обновлением не менялись.

Снимок рабочего плеера и технический результат без личных данных сохранены
