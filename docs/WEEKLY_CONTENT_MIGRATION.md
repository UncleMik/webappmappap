# Перенос недельного контента

Согласован 2026-10-08. Рабочий источник — таблица `weekly_content` в
`/opt/wep_pril/data/articles.sqlite`, API — `GET /api/weekly-content`.

Перенос включает 42 записи «Малыш», 42 записи «Мама», календарь для 42
недель (14 событий и 3 примечания), 81 уникальное изображение. Проверена
идентичность всех полей исходных недельных данных и байтов изображений.
Исходная версия для сверки — Git `30094b8`.

Иллюстрации находятся в `/opt/wep_pril/uploads/weekly/`; имя файла — SHA-256
его содержимого. Картинки и база включаются в существующую ежедневную
резервную копию. Перед переносом сделаны дополнительные копии базы,
изображений, кода, фронта и конфигурации nginx.

`backend/seed/weekly-content.json` — архив первого импорта, а не источник
данных работающего фронта. Изображения импорта не публикуются в Git.
Повторно подготовить исходный архив можно командой
`node tools/export-weekly-content.mjs 30094b8`.

Для обновления контента загрузить изменённый JSON и изображения на сервер,
создать резервную копию и выполнить:

```sh
node /opt/wep_pril/backend/import-weekly-content.mjs \
  /opt/wep_pril/backend/seed/weekly-content.json \
  /opt/wep_pril/data/articles.sqlite /opt/wep_pril/uploads
```

Импорт проверяет данные, хеши и наличие иллюстраций до записи. Запись
выполняется транзакцией; прежние ограничения публикации и доступа сохраняются.
После изменения изображения его новое имя следует указать в JSON.
Повторная публикация фронта и перезапуск API для обновления контента не нужны.
Кеш API действует 60 секунд; уже открытый экран обновится при перезагрузке.

Во фронте остаются отображение, навигация, формы личных записей и
демонстрационный фактический срок. При недоступности API показываются ошибка
и повторная попытка без подстановки встроенной копии недельных данных.
Админ-панель, вход и синхронизация личных записей в этот перенос не входят.
