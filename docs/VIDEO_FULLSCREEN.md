# Полный экран видео — 19 октября 2026 года

## Обновление 20 октября 2026: пропорции обычного плеера

Обычная область видео подстраивается под фактические размеры записи
через общий `--video-aspect-ratio` в video.css. video-fullscreen.js
обновляет его при loadedmetadata и resize каждого подключённого HTML video.
До получения размеров video.js вписывает недельную обложку по её пропорциям;
после получения размеров видео поздняя загрузка обложки их не меняет.

Полный экран сохраняет contain: при несовпадении формата записи и экрана
поля остаются, чтобы показывать запись целиком. После выхода восстанавливается
размер записи. Проверены настоящий вход/выход в Chromium, три исходных
урока и вертикальная/квадратная тестовые записи. Проверки выполнены на
изолированной странице с моделируемой сессией; серверные правила доступа
не менялись.

Текущая точечная публикация обновляет video.css, video.js,
video-fullscreen.js и версии их подключения в video.html. Используется
согласованный SSH-доступ из deploy/SSH.md: до записи проверяются хеши,
предыдущие файлы сохраняются в закрытую папку root. Базы, службы и nginx
не меняются. Ниже сохранено историческое описание первого выпуска;
его старый скрипт и хеши не применять к текущим файлам.


Обновление 20 октября: по прямому запросу пользователя кнопка расположена
в нижнем правом углу плеера, с отступами минимум 12 px и учётом safe area.
Размер области нажатия — 44×44 px. На действующем сайте проверены ширины
320, 400 и 520 CSS px, отсутствие горизонтального переполнения, запуск
настоящего видео и доступность кнопки. Автоматизированный Chrome отклонил
запрос полного экрана; проверка на физических телефонах остаётся открытой.
Изменён только CSS и его версия в HTML. Серверные копии сохранены в
`/root/webpril-fullscreen-corner-20261020-115212/backup`.
Для последующих согласованных работ в этой сессии проверен SSH-доступ;
описанное ниже отсутствие SSH относится к первоначальному выпуску 19 октября.

Пользователь выбрал комбинированный вариант: кнопка раскрывает видео на весь
экран и запрашивает горизонтальную ориентацию для горизонтальной записи. Если
браузер не разрешает поворот, видео остаётся на весь экран с подсказкой
повернуть телефон. После выхода возвращаются прежняя страница и её кнопки.
Пропорции записи сохраняются без обрезки; вертикальную запись принудительно
не поворачиваем.

Изменение ограничено `Фронт/video.html`, `Фронт/video.css` и новым
`Фронт/video-fullscreen.js`. Выдача видео, вход, платёжный доступ и серверные
службы не меняются. На iPhone Safari собственный полноэкранный плеер управляет
видео и может не разрешить приложению заблокировать ориентацию; подсказка
показывается перед входом в него.

В локальном Chromium проверены ширины 320, 390, 500 и 1280 px, запуск,
пауза и перемотка настоящего MP4, повторный вход и выход из полного экрана.
Отказ и успех запроса поворота, события нативного плеера iPhone, а также
сценарии входа и API на этой проверке моделировались. Также моделировались
позднее завершение блокировки ориентации после выхода
из полного экрана и вертикальная запись, для которой блокировка не нужна.
Реальные Android и iPhone остаются непроверенными.

Для публикации использовать только точечный скрипт
`deploy/publish-video-fullscreen.py` после коммита трёх файлов в GitHub.
Он принимает полный SHA коммита, скачивает только эти файлы, сравнивает хеши
старой и новой версии, сохраняет резервную копию и проверяет опубликованные
файлы и доступность API. Службы не перезапускаются. Старые хеши `video.html`
и `video.css` сверены 19 октября с живым HTTPS сайта. `video.html` побайтно
совпадает с коммитом `3388f63`; в опубликованном CSS одно существующее
правило центрирования обложки находится в конце файла, а в Git — выше.
Других отличий нет; скрипт принимает только фактический хеш живого CSS.
Нового файла на сервере до выпуска нет. Скрипт использует зафиксированную
версию функции атомарной замены и отката из `deploy/publish-weekly-videos.py`.
