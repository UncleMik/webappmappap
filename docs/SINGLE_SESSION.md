# Одна активная сессия на аккаунт

Согласовано пользователем 24 октября 2026: последний успешный вход
завершает предыдущие сессии аккаунта. Обычные вкладки одного профиля браузера
разделяют cookie и работают вместе; другой браузер, инкогнито или устройство
создают новый вход. Это ограничение сессий, без привязки к IP или устройству.

## Поведение

- Сессия заменяется только при успешном завершении входа по подтверждённому
  коду. Запрос письма, неверный код и ошибка завершения сохраняют прежний вход.
- Отзыв старых токенов и выдача нового выполняются одной транзакцией под
  блокировкой email. Частичный уникальный индекс PostgreSQL разрешает только
  одну неотозванную сессию аккаунта. Два одновременных входа сериализуются;
  остаётся последняя успешно записанная сессия.
- Все серверные проверки, включая Nginx, API курсов, видео и сохранение
  профиля, отвергают отозванную cookie. Выход со старой cookie не завершает новую.
- Срок сессии остаётся абсолютным: до 30 дней. Обновление страницы его не продлевает.
- Открытая вкладка проверяет сессию раз в 30 секунд, пока видима. Фоновая
  проверка не скрывает действующую страницу. Первое открытие, возврат из
  скрытой вкладки и истории сохраняют прежнее правило: скрывать до проверки.
- Таймер один на внешнее окно, без отдельных таймеров в сохранённых панелях.
  При отзыве внешний gate скрывает страницу, останавливает video/audio,
  удаляет iframe и заменяет всё окно формой входа с адресом возврата и текстом:
  «Выполнен вход в другом браузере или на другом устройстве. Войдите заново.»
- Ошибка проверки оставляет доступ закрытым. Долгий ответ после pagehide
  или скрытия вкладки не должен повторно показать её содержимое.

Серверный отзыв действует после фиксации нового входа. Открытый экран
обнаруживает его при ближайшей успешной проверке, обычно в пределах 30 секунд;
задержки сети и приостановка браузера могут увеличить этот срок. Уже полученные
данные и ранее выданные прямые ссылки MP4 GetCourse отозвать этим нельзя.
Текущая задача не меняет согласованный порядок доставки видео.

## Миграция и выпуск

`backend/auth/single-session-migration.sql` применяется в транзакции владельцем
схемы. Миграция отзывает истёкшие сессии, оставляет каждому аккаунту последнюю
созданную действующую сессию и создаёт уникальный индекс. Равное время
разрешается детерминированно по хешу токена. Повторный запуск идемпотентен.
Отозванные строки содержат прежние хеши токенов и удаляются обычной очисткой
по исходному сроку сессии; новый журнал пользовательских данных не создаётся.

`deploy/publish-single-session.py <полный SHA> [--apply]` выполняется под root
на Timeweb. Без `--apply` только скачивает восемь файлов закреплённого коммита,
сверяет SHA-256 и исходные серверные файлы. Применение:

1. Готовит закрытую копию прежних файлов и manifest в `/root/`.
2. Кратко останавливает только службу входа, сохраняет полный `pg_dump`
   отдельной базы авторизации и применяет миграцию. Старый процесс не работает
   с новым индексом; защищённые запросы на время остановки закрыты.
3. Атомарно заменяет проверенные файлы, запускает службу и проверяет здоровье,
   окончательные хеши и отсутствие нескольких неотозванных сессий аккаунта.

Nginx, секреты, покупки, профили и база статей не меняются. При ошибке
возвращаются прежние файлы и индекс; перед возвратом старого кода отозванные
токены удаляются, чтобы он не оживил завершённые входы. Полная база автоматически
не восстанавливается поверх новых пользовательских данных. Неизвестные и
конкурирующие изменения не перезаписываются. Копия базы остаётся для ручного
восстановления после отдельного согласования. GitHub Pages не используется.

Если сам откат не завершился, доступ остаётся закрытым. Под root проверить
состояние `wep-pril-auth`, закрытый manifest и причину ошибки. До запуска
старого кода удалить только отозванные токены и снять новый индекс, затем
восстановить соответствующие файлы по manifest и проверить здоровье службы.
Не подменять всю базу дампом и не запускать старый код с отозванными строками.

Вкладка, открытая ещё до выпуска, получит новый таймер при обновлении или
повторном открытии. Серверный отзыв старого входа действует независимо от
версии уже загруженного интерфейса.

## Проверки

- `node --test test/*.test.mjs` из `backend/`: общий набор бэкенда, включая
  замену сессий, откат неуспешной замены, разные аккаунты, конкурирующие входы,
  старые cookie во всех auth-маршрутах, ограничение PostgreSQL и миграцию.
- На отдельной настоящей PostgreSQL выполнены проверки auth/profile/access
  и single-session; PGlite не используется как доказательство конкурентности.
- `node --test tools/test-single-session-gate.mjs`: фоновые проверки, один
  таймер, iframe, media, причина выхода, сеть и поздние ответы после скрытия.
- `python -m unittest deploy/test_publish_single_session.py`: резервная копия,
  применение, откат после ошибки здоровья/миграции и сохранение чужой правки.
- Два независимых Chromium на временном изолированном стенде: email/код,
  неверный код без выхода, новая сессия и выход прежней, сохранённые панели,
  обновление новой сессии. Письма и GetCourse заменены тестовыми адаптерами.
  Экран причины выхода проверен на 390×844, горизонтальной прокрутки нет.

Итоговые результаты: 84/84 проверки бэкенда, 27/27 проверок auth/profile/access
на настоящей PostgreSQL, 8/8 проверок клиентского gate и безопасного возврата,
4/4 проверки публикации. На изолированном стенде отдельно подтверждена
остановка проигрываемого видео при замене сессии.

## Рабочий сайт — проверено 24 октября 2026

Выпуск `fe92376` установлен на Timeweb; все восемь серверных файлов сверены
по SHA-256. Миграция выполнена, служба входа активна. Закрытая копия файлов
и полный дамп auth-базы: `/root/webpril-single-session-20261023T215238Z/`.

Через `https://app.legkie-rody.ru/` проверен отдельный временный синтетический
аккаунт без покупок и вызовов почты/GetCourse. Контрольные подтверждённые
запросы входа созданы root-инструментом только для этого аккаунта; выдача
и замена сессий происходили через опубликованный `/api/auth/complete`.
Повторная доставка настоящего email-кода этим не проверена.

- После второго входа прежние cookie получают 401 от auth/check, видео,
  курсов, API статей, недельного контента и защищённого JS. GET и HEAD
  страницы профиля возвращают 302 ко входу; session не выдаёт пользователя
  и возвращает причину `session_replaced`.
- Новая сессия получает 204 от auth/check и 200 для профиля; сохраняется
  после обновления и после logout с прежней cookie. В базе ровно одна
  неотозванная сессия контрольного аккаунта.
- В независимых Chromium на рабочем HTTPS обе вкладки старого входа
  перешли на форму с объяснением, сохранённая панель Клуба исчезла.
  Возврат через историю не показал раздел приложения. Новая сессия
  осталась рабочей. Мобильная форма 390×844 без горизонтальной прокрутки.
- Контрольные пользователь, сессии и запросы входа удалены; служба
  проверена после очистки. Временный локальный стенд и созданные для
  проверки браузеры закрыты. Автозапуск и внешний туннель не включались.

Нагрузка 1000 активных пользователей и физические телефоны не проверялись.
Правило сессий не защищает от копирования уже полученных файлов/токенов;
усиление доставки видео и привязка к устройству в эту задачу не входят.
