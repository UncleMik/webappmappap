# SSH на действующий сервер Timeweb

С 10 ноября 2026 года прямой SSH-вход `root` запрещён. Вход по паролю
и keyboard-interactive отключён для SSH. Доступ выполняется только по
ключу под отдельным администратором `webpril-admin`.

## Подключение с настроенного рабочего места

```powershell
ssh webpril-timeweb
```

Alias в `%USERPROFILE%\.ssh\config` использует `User webpril-admin`,
существующий ключ `%USERPROFILE%\.ssh\id_ed25519_webpril_timeweb`,
`IdentitiesOnly yes` и `StrictHostKeyChecking yes`.
Закрытый ключ не копировать на сервер, в чат, в репозиторий или в архивы
публикации. Для подключения с другого устройства отдельно добавить его
публичный ключ; не включать парольный вход или root SSH ради переноса.

Обычная сессия работает от имени `webpril-admin`. Команды, которым нужны
административные права, выполняются явно через `sudo -n`:

```powershell
ssh webpril-timeweb 'id -un; sudo -n id -u'
ssh webpril-timeweb 'systemctl is-active wep-pril wep-pril-auth nginx'
```

Первый пример должен вернуть `webpril-admin` и `0`. Администратор имеет
право выполнять команды через sudo без интерактивного пароля: это
сохраняет обслуживание сервера и существующие процедуры публикации.
Права пользователей приложения и служб не менялись.

## Передача файлов и публикация

SCP/SFTP входят под `webpril-admin`, поэтому не могут напрямую записывать
в `/root`, `/etc` и защищённые каталоги приложения. Сначала передавать
артефакт в отдельный приватный каталог внутри `/home/webpril-admin`, затем
проверять контрольные суммы и запускать согласованный серверный скрипт
через `sudo -n python3 ...`.

Сохраняются прежние требования: резервная копия заменяемых файлов,
проверка SHA-256, атомарная замена, проверка конфигурации перед reload
и проверка опубликованного сценария. Старые команды с явным
`root@...` или `username='root'` необходимо переводить на нового
администратора; ослаблять SSH-политику для их совместимости нельзя.

## Действующая политика

Параметры находятся в `/etc/ssh/sshd_config.d/00-webpril-key-only.conf`,
подключаемом раньше настроек cloud-init:

```text
PermitRootLogin no
PubkeyAuthentication yes
PasswordAuthentication no
KbdInteractiveAuthentication no
AuthenticationMethods publickey
```

Проверка синтаксиса: `sudo -n sshd -t`. Эффективные значения проверять
через `sudo -n sshd -T`, учитывая порядок Include и возможные Match-блоки.
Разрешения sudo заданы отдельно в `/etc/sudoers.d/90-webpril-admin` и
проверены `visudo`.

Системный root не удалён и может использоваться через sudo; доступ через
консоль провайдера этой настройкой не изменялся и в ходе переключения
не проверялся.

## Подтверждённая проверка 10 ноября 2026

- До отключения root создано отдельное соединение администратора по ключу
  и проверен `sudo -n`.
- После перечитывания SSH повторно открыто новое соединение администратора.
- Передача файла проверена записью, чтением и удалением искусственного
  файла в домашнем каталоге администратора.
- Обычная команда `ssh webpril-timeweb` использует нового администратора.
- Новая попытка SSH-входа `root` с прежним рабочим ключом получила
  `Permission denied`.
- Службы SSH, Nginx, API статей и авторизации активны. Публичная форма
  входа возвращает 200; анонимная проверка доступа — 401.
- Сохранены закрытые копии серверной и локальной конфигурации.
  Временный автоматический откат отменён после проверки нового доступа.

При следующих изменениях SSH сначала сохранить рабочий сеанс и убедиться,
что есть проверенный путь возврата доступа. Не отключать текущие ключи
до успешной проверки нового входа в отдельном соединении.
